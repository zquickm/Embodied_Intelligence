# 阶段一详细实行步骤：选择并验收现成底盘

## 1. 本阶段只解决什么

阶段一的目标不是“做出完整机器人”，而是选到并验收一套**可继续开发、能够安全停车、能够返回真实运动反馈**的现成差速底盘。

完成本阶段时，应得到以下四类交付物：

1. 一套能通电、前进、后退、转向和停车的完整底盘。
2. 型号、控制板、固件、供电、通信、尺寸、载荷和安装接口资料。
3. 控制命令、编码器或里程计反馈、主动停车及断联停车的验收证据。
4. 一份明确的结论：通过、限期补资料，或退货。

本阶段不做电机 PID 重写、控制板设计、固件逆向、机械臂上车或导航调参。这些工作现在做只会扩大故障面。

---

## 2. 开始条件

开始购买前，应满足以下条件：

- 阶段 0 的 Ubuntu 24.04、ROS 2 Jazzy 基础环境已经能运行；官方仍将 Ubuntu 24.04 Noble 列为 Jazzy 的支持平台。[ROS 2 Jazzy 官方安装说明](https://docs.ros.org/en/jazzy/Installation/Ubuntu-Install-Debs.html)
- 已准备卷尺、电子秤、万用表、电脑、手机录像、绝缘垫和一块可将车轮悬空的稳固支撑物。
- 有至少 2 m × 2 m 的空旷低速测试区域，周围没有台阶、玻璃、宠物和儿童。
- 预算按“可运行整套总价”计算，而不是只看裸车架价格。

如果阶段 0 尚未完成，也可以做资料筛选和卖家远程验收，但不要把“商品页写着支持 ROS”当成已验证兼容。

---

## 3. 第一步：冻结需求，不先看商品

先建立一张 `底盘需求表`，用实测或保守估算填写以下内容。

### 3.1 统计将来要放到底盘上的质量

| 部件 | 估算质量 | 是否已实测 | 备注 |
|---|---:|---|---|
| 机械臂从臂 |  |  | 包含夹爪 |
| 机械臂支架和安装板 |  |  | 不要漏算金属板 |
| 上位机 |  |  | 笔记本不上车则写 0 |
| 电池和稳压模块 |  |  | 采用实际整套质量 |
| 相机、雷达和支架 |  |  | 包含线材 |
| 其他线束与外壳 |  |  | 先预留 |
| 上装合计 |  |  | 上述项目之和 |

初筛时可把“所需额定载荷”设为：

`所需额定载荷 = 上装合计 × 1.5`

这里的 1.5 是保守筛选余量，不是通用行业认证值。最终仍须遵守厂家给出的载荷条件，并检查重心高度、加减速和地面状况。机械臂伸出后会产生倾覆力矩，因此“静态能放得下”不代表“运动时不会翻”。

### 3.2 冻结尺寸和安装要求

至少记录：

- 底盘允许的最大长、宽、高。
- 顶板可用平面尺寸。
- 安装孔的孔径、孔距、螺纹规格和顶板厚度。
- 机械臂底座直径及线缆出口位置。
- 希望保留的雷达视野和相机视野。
- 门宽、桌腿间距、计划通过的最窄通道。

判定规则：卖家不能提供尺寸图或实拍尺量证据，就不能确认“能装”，只算未知项。

### 3.3 冻结控制与反馈要求

以下六项全部设为硬门槛：

- 能从电脑通过 USB、串口或有文档的网络接口控制，不只支持手机遥控。
- 能设置前进速度和转向速度，且速度单位或换算关系有说明。
- 有左右轮编码器，SDK 或驱动能读到轮速、编码器计数或里程计中的至少一种真实反馈。
- 有明确的停止命令。
- 上位机停止发命令或通信断开后，底盘能在可配置或有说明的短时间内自动停车。
- 能获得准确的控制板型号、固件版本和接口资料。

ROS 2 的差速控制参考实现同时考虑轮子反馈、里程计和速度命令超时；其中命令超时用于把过期速度命令判定为失效。因此，把“断联自动停车”作为硬门槛是合理的安全要求。[ros2_control 差速控制器文档](https://control.ros.org/jazzy/doc/ros2_controllers/diff_drive_controller/doc/userdoc.html)

### 3.4 冻结预算

总价应按下式统计：

`整套总价 = 底盘 + 运控板 + 电池 + 充电器 + 通信线/转换器 + 缺失轮组或编码器 + 运费 + 必要维修`

若当前百元级预算只能买到裸车架、未知控制板或坏电池，则本阶段保持仿真或借用设备，不为了“先有实物”购买无法开发的残套。

本步完成标志：需求表中所有硬门槛都有明确值，未知项已被列出，没有使用“应该可以”作为结论。

## 4. 第二步：收集 3 个候选，不立即下单

每个候选单独建立资料夹，命名为 `候选A_品牌_型号`，保存商品页截图、卖家答复、视频和文档。只保留最多 3 个候选，更多候选通常只会增加比较成本。

向卖家发送以下询问模板：

> 请确认完整品牌和型号、底盘版本、运动控制板型号及固件版本，并提供实拍铭牌。请列出本单实际包含的车架、电机、编码器、轮子、控制板、电池、充电器、通信线和转接器。请提供控制协议、Python SDK 或 ROS 2 驱动的实际下载地址，以及支持的 Ubuntu/ROS 版本。请说明供电电压范围、接口类型、波特率或网络参数、速度单位、编码器或里程计反馈、停止命令和断联自动停车时间。请提供尺寸图、载荷说明、轮径、轮距、安装孔位，并录制前进、后退、左右转、停车及电脑端反馈数据的视频。

收到链接后要实际打开，不接受以下替代说法：

- “网上能搜到”。
- “支持 ROS”，但不给仓库和分支。
- “有编码器”，但程序读不到反馈。
- “可以二次开发”，但不给协议或 SDK。
- “电池正常”，但拒绝展示充电和连续运行。

本步完成标志：每个候选都有准确型号、附件清单、可下载资料和实机视频；缺一项就在比较表中标为未知。

## 5. 第三步：先做否决检查，再评分

### 5.1 出现任一情况直接淘汰

- 控制板型号、固件版本或接口定义无法确认。
- 只有遥控器或手机 App，没有电脑控制接口。
- 没有编码器，或卖家无法证明程序可读取真实反馈。
- 通信中断后电机会继续保持最后速度，且无法配置超时停车。
- 电池鼓包、漏液、外皮破损，或充电器与电池规格不匹配。
- 电机、控制板、电池或通信线缺失后，补齐总价超过预算。
- 资料只适用于 ROS 1 或明显不同硬件版本，且没有可接受的迁移路径。
- 卖家拒绝录制包含设备、控制端和反馈端的连续视频。

### 5.2 对剩余候选按 100 分评分

| 项目 | 分值 | 满分条件 |
|---|---:|---|
| 资料完整性 | 25 | 协议、SDK/驱动、尺寸、供电、版本资料均可下载 |
| 控制与反馈 | 25 | 速度控制、停止、编码器/里程计、电源状态均能读取 |
| 安全行为 | 20 | 有急停或可靠停止方式，断联后自动停车可验证 |
| ROS 2 兼容性 | 15 | 明确支持当前 ROS 2；仓库、分支和安装步骤可查 |
| 机械适配 | 10 | 载荷、尺寸、孔位和重心满足需求 |
| 总成本 | 5 | 所需附件齐全且总价在预算内 |

建议只购买总分达到 80 且没有否决项的候选。分数最高但存在安全否决项，仍然不能购买。

## 6. 第四步：购买前远程预验收

要求卖家录制一段尽量连续、不剪辑的视频，画面同时能辨认底盘和控制端。

按以下顺序演示：

1. 展示底盘、控制板、电机、电池、充电器、通信线和铭牌。
2. 展示当前固件版本或控制软件版本。
3. 轮子悬空，执行低速前进、后退、左转、右转和停止。
4. 展示编码器、轮速或里程计数值随轮子运动变化，并确认左右轮方向关系合理。
5. 落地低速直行和转向，不能出现明显卡死、失控或持续异响。
6. 在低速运动中停止控制程序、拔掉通信线或使用厂家规定的方法模拟断联，证明底盘自动停车。
7. 重新连接并恢复控制，证明设备不是一次性偶然工作。
8. 展示电池充电状态和至少 10 分钟连续低速运行。

这里最重要的是第 6 项。只展示点击“停止”按钮，不等于已经验证通信丢失后的自动停车。

预验收通过后，在交易沟通中写明：实际包含的附件、已展示的功能、资料链接、允许的到货测试时间以及不符时的退货条件。

---

## 7. 第五步：到货后先做静态检查

不要收到货就通电。先录像开箱，并按以下顺序检查：

1. 对照成交清单逐件点数，拍摄各部件和铭牌。
2. 检查车架是否弯曲，轮子是否开裂，联轴器和紧固件是否松动。
3. 手动缓慢转动轮子，确认没有明显卡滞；带减速器的电机可能阻力较大，不要强拧。
4. 检查线束是否破皮、压伤、烧焦，连接器是否松脱或被改线。
5. 检查电池是否鼓包、漏液、异常气味或外皮破损；有异常立即隔离，不充电、不通电。
6. 根据说明书核对电池标称电压、满电电压、极性、连接器和控制板允许输入范围。
7. 用万用表测电池端电压和极性。探针不要造成短路；不熟悉万用表时应让有经验的人协助。
8. 检查电源开关、保险丝和可触及的停止方式。

静态检查通过条件：附件齐全、机械无明显损伤、线束无裸露、电池外观正常、电压和极性与资料一致。

任一电气条件不明时停止，不采用“插上试试”的方式确认接口。

## 8. 第六步：电脑连接与身份确认

下面命令均在 Ubuntu 24.04 终端执行，只用于读取状态，不会控制电机。

```bash
lsusb
```

作用：列出 USB 设备。连接底盘前后各运行一次，可帮助判断新增的是哪一个 USB 转串口或控制器。

```bash
ls -l /dev/serial/by-id/
```

作用：显示带稳定设备标识的串口路径。优先记录这里的路径，而不是只记可能在重启后变化的 `/dev/ttyUSB0`。

```bash
dmesg --follow
```

作用：实时观察内核发现或断开 USB/串口设备时的消息。看完后按 `Ctrl+C` 退出；它只停止查看日志，不会关闭设备。

如果该命令提示权限不足，只记录这一现象即可，不要把它误判为底盘故障；仍可先用前两条命令确认设备，之后再按当前电脑的管理员策略处理日志权限。

如果厂家提供 ROS 2 驱动，先严格按照厂家文档启动，再执行：

```bash
ros2 topic list -t
```

作用：列出当前 ROS 2 话题及消息类型，用于发现真实的速度输入、编码器、里程计和电源状态接口。ROS 2 官方将话题用于连续数据流，并提供命令行检查工具。[ROS 2 Jazzy 接口说明](https://docs.ros.org/en/jazzy/How-To-Guides/Topics-Services-Actions.html)

```bash
ros2 topic info -v <反馈话题名>
```

作用：查看指定话题的消息类型、发布者、订阅者和 QoS。把 `<反馈话题名>` 替换成上一步实际发现的话题；不要原样输入尖括号内容。

```bash
ros2 topic echo --once <反馈话题名>
```

作用：只读取并显示一条反馈，便于确认确实有数据而不让终端持续刷屏。

```bash
ros2 topic hz <反馈话题名>
```

作用：测量反馈发布频率。运行数秒后按 `Ctrl+C` 停止统计，并记录平均频率。

不要在不知道消息类型、单位、限幅和停止方式时照搬网上的 `ros2 topic pub` 运动命令。底盘可能接收 `Twist`、`TwistStamped` 或私有协议，错误命令可能无效，也可能造成突然运动。

## 9. 第七步：悬空低速通电验收

首次运动测试必须让驱动轮可靠悬空，底盘不能从支撑物上滑落。机械臂、雷达和其他载荷此时都不要安装。

执行顺序：

1. 电脑先打开厂家状态读取程序，但暂不发送运动命令。
2. 接通信线，再按厂家顺序接电和开机。
3. 记录固件版本、电池电压、错误码和初始编码器值。
4. 发送厂家允许的最小非零前进速度，持续不超过 1 秒，然后主动发送停止命令。
5. 检查左右轮是否同向、转速是否接近、停止是否及时。
6. 依次测试后退、左转、右转，每次只执行一个动作并立即停止。
7. 每个动作同时记录控制值和左右反馈值，确认反馈不是固定值或由命令值直接伪造的开环结果。
8. 让轮子停住，观察反馈是否回到接近零，检查电机和控制板是否异常发热、异味或持续报警。

若出现方向相反、单轮不转、剧烈抖动、持续异响或停止无效，立即断开动力并记录，不进入落地测试。

---

## 10. 第八步：落地低速基础运动验收

通过悬空测试后，在空旷区域贴出 1 m 直线和起点。测试人员应始终能立即触及实体电源开关或停止装置。

按以下顺序，每项至少重复 3 次：

1. 低速前进约 0.5 m，主动停止。
2. 低速后退约 0.5 m，主动停止。
3. 原地或小半径左转约 90°，停止。
4. 原地或小半径右转约 90°，停止。
5. 沿 1 m 标线直行，记录终点横向偏差。
6. 连续运行 10 分钟，包含启停和转向，观察掉线、复位、异常发热和电压下降。

阶段一不要求把直行和角度误差校到很小；这里只判断底盘是否具备可重复运动的基础。轮径、轮距和里程计比例的正式校准属于阶段三。

建议记录：动作、设定速度、持续时间、实际距离或角度、左右反馈、是否成功、异常现象和视频文件名。

---

## 11. 第九步：安全停车与异常验收

所有异常测试先使用最低速度，测试人员准备随时断开动力。

### 11.1 主动停止

运动中发送厂家规定的停止命令，记录从命令发出到车体完全停止的大致时间和距离。重复 3 次，三次都必须有效。

### 11.2 控制程序退出

运动中关闭上位机控制程序。底盘必须因本地控制器的超时机制自动停车，不能依赖已经退出的程序继续发送零速度。

### 11.3 通信断开

按厂家允许的方法断开通信链路，验证底盘自动停车。不要在可能拉弧的大电流动力接头上用“拔线”模拟；应断开 USB、网络或使用厂家提供的测试方法。

### 11.4 重启恢复

重新连接后，底盘不应自行恢复断联前的最后速度。只有再次收到有效命令时才允许运动。

### 11.5 非法或超范围输入

只在厂家文档给出安全测试方式时执行。确认驱动能够拒绝、报错或限幅，而不是让底盘无约束执行。阶段一不自行构造未知协议帧。

通过条件：主动停止、程序退出停车、通信断开停车和重连不自启动四项全部通过。任何一次出现持续运动，都应判为安全验收失败。

## 12. 第十步：整理资料并作出最终判定

建立如下归档结构：

```text
底盘验收/
├── 01_购买与附件清单/
├── 02_厂家文档与驱动/
├── 03_型号固件与配置/
├── 04_开箱和静态检查/
├── 05_悬空运动测试/
├── 06_落地运动测试/
├── 07_断联停车测试/
└── 08_验收结论.md
```

每个资料链接都保存访问日期和本地副本；记录仓库地址、分支或标签、提交号，不只写“GitHub 上的驱动”。

最终按以下规则判定：

### 通过

- 附件、型号和资料与成交说明一致。
- 控制与真实反馈可用。
- 四项停车安全测试全部通过。
- 供电、载荷、尺寸和安装接口符合需求。
- 连续低速运行没有掉线、复位、异常温升或异味。

### 限期补资料

只允许用于不影响安全和基本控制的小缺项，例如缺少电子版尺寸图但卖家能提供准确实测。必须写明补齐期限；在补齐前不进入改装。

### 退货或淘汰

出现控制板版本不符、反馈缺失、断联不停、电池异常、关键附件缺失、文档无法使用或整套成本失控中的任一项。
