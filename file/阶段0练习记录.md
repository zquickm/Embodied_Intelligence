# 阶段 0 练习记录

## 练习：发送速度命令 + 读取里程计（2026-10-17 完成）

对应总计划阶段 0 第 4 步：写一个 Python ROS 节点，发送低速命令并主动停止，再订阅里程计输出当前位置。

**代码**：`ros2_ws/src/tb3_learning/tb3_learning/move_and_report.py`（入口 `move_and_report`，已注册进 `setup.py`）

**节点行为**：

1. 启动后静默等待，直到收到第一帧 `/odom`（说明 DDS 连接就绪）才开始计时。
2. 以 10 Hz 向 `/cmd_vel` 发送 `linear.x = 0.1` 的 TwistStamped，持续 3 秒。
3. 发送一次全零 TwistStamped 作为主动停止命令。
4. 全程以约 50 Hz 打印里程计位置。

**实测结果**（burger + turtlebot3_world）：

- 里程计连接后小车前进，x 从 0 爬升到 **0.196 m** 后稳定不动，y 全程约 0。
- 理论值 0.1 m/s × 3 s = 0.3 m，实测偏小并带约 0.8 s 的起步延迟，原因是：速度命令是"目标值"，DiffDrive 有加速度限制，起步要爬坡、停止要减速；实际位移是速度曲线下的面积。这解释了为什么真机需要阶段 3 的速度限制配置与误差记录。

## 环境与话题（turtlebot3_burger_bridge.yaml）

| ROS 话题 | 消息类型 | 方向 | 说明 |
| --- | --- | --- | --- |
| `/cmd_vel` | `geometry_msgs/msg/TwistStamped` | ROS→GZ | 速度命令入口，注意不是 Twist |
| `/odom` | `nav_msgs/msg/Odometry` | GZ→ROS | 里程计位姿+速度，约 50 Hz |
| `/scan` | `sensor_msgs/msg/LaserScan` | GZ→ROS | 激光雷达 |
| `/imu` | `sensor_msgs/msg/Imu` | GZ→ROS | IMU |
| `/joint_states` | `sensor_msgs/msg/JointState` | GZ→ROS | 轮子关节（由 robot_state_publisher 转成 TF） |
| `/tf` | `tf2_msgs/msg/TFMessage` | GZ→ROS | odom→base_footprint 位姿 |
| `/clock` | `rosgraph_msgs/msg/Clock` | GZ→ROS | 仿真时间 |

桥接器由 `ros2 launch turtlebot3_gazebo turtlebot3_world.launch.py` 启动，配置文件在 `/home/venus/turtlebot3_ws/install/turtlebot3_gazebo/share/turtlebot3_gazebo/params/`。

## 启动步骤（重启后复验用）

**终端 A —— 仿真**：

```bash
source /opt/ros/jazzy/setup.bash
source /home/venus/turtlebot3_ws/install/setup.bash
export TURTLEBOT3_MODEL=burger
ros2 launch turtlebot3_gazebo turtlebot3_world.launch.py
```

等 Gazebo 窗口出现、小车出现后再开终端 B。

**终端 B —— 编译（如有改动）并运行练习节点**：

```bash
source /opt/ros/jazzy/setup.bash
cd ~/projects/embodied-intelligence/ros2_ws
colcon build --packages-select tb3_learning
source install/setup.bash
ros2 run tb3_learning move_and_report
```

**预期**：几秒内打印 `里程计已连接，开始计时前进` → 小车直行约 3 秒 → `已发送停止命令` → x 稳定在 0.196 左右。`Ctrl+C` 干净退出。

**注意**：所有终端必须都带 `ROS_LOCALHOST_ONLY=1`（已写入 `~/.bashrc`）；混用带与不带的终端会互相看不见。

## 踩坑记录

1. **venv 与 ROS 冲突**：虚拟环境看不到系统包（PyYAML 等），`import rclpy` 报 `No module named 'yaml'`。做 ROS 用系统 Python，不激活 venv。
2. **WSL2 下 DDS discovery 极慢**（约 30 s）：WSL2 虚拟网卡的组播不可靠。`export ROS_LOCALHOST_ONLY=1` 强制本机回环后秒连。Jazzy 提示已改名为 `ROS_AUTOMATIC_DISCOVERY_RANGE=LOCALHOST`，旧变量仍有效。
3. **连接建立前的命令会丢失**：ROS 2 不为未连接的发布者缓存消息。对策：节点先等第一帧里程计到达再开始发命令（门控设计）。
4. **Ctrl+C 时补发零速报 RCLError**：rclpy 的 SIGINT 处理器先关闭 ROS 上下文，`finally` 里的 publish 已无效。用 try/except 包裹尽力而为；真正的安全保障是底盘收到不到新命令时的超时停车（阶段 2 要在真机验证的行为）。
5. **调试工具**：`ros2 topic info/hz/echo` 查 ROS 侧；`gz topic -i/-e` 查 Gazebo 侧；`ros2 daemon stop` 清掉过期守护进程。
