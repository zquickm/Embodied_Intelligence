## 2. 算法选择：原计划没有指定，这里定下来

**问题**：计划里 A2 只写了"CartPole、LunarLander 各训练到目标分"，**没写用什么算法**。而且模块 A 从头到尾**没有 DQN 阶段**（A3 是 PPO、A4 是 SAC），但 A2 的验收标准要求解释 on/off-policy 并举算法例子——只做一个算法无法对比。

**决定**：

| 任务 | 算法 | 为什么 |
|---|---|---|
| CartPole-v1 | **手写 REINFORCE + baseline** | 直接对应"能手推策略梯度公式"；是 on-policy 的原型；代码短到能完全手写 |
| LunarLander-v3 | **SB3 DQN** | 任务更难（8 维观测、需精确控制着陆姿态），REINFORCE 难以稳定达标；DQN 是 off-policy 的原型，正好补齐模块 A 缺失的这一环 |

**这个搭配的额外收益**：两个算法恰好构成 on-policy / off-policy 的对照，第 5 条验收标准不再是背概念，而是有自己跑出来的两个实例可以对比。

**为什么 CartPole 不用 DQN**：实测 DQN 在 CartPole 上 20k 步只有 9.5 分（低于随机策略），而手写 REINFORCE 400 集就到 351.8 分。CartPole 的观测是 4 维连续值、奖励简单，策略梯度比 Q-learning 更直接适用。**不是 DQN 不行，是它需要更多步数（通常 50k+）。**

## 3. 理论（验收标准 3、4、5 的答案）

### 3.1 MDP 五元组

强化学习问题形式化为 **马尔可夫决策过程** $\mathcal{M} = \langle \mathcal{S}, \mathcal{A}, P, R, \gamma \rangle$：

| 符号 | 名称 | 含义 | CartPole 实例 |
|---|---|---|---|
| $\mathcal{S}$ | 状态空间 | 所有可能的状态 | 小车的 4 维向量：位置、速度、杆角、杆角速度 |
| $\mathcal{A}$ | 动作空间 | 所有可选动作 | $\{0, 1\}$ = 左推 / 右推 |
| $P(s'\|s,a)$ | 转移概率 | 在 $s$ 执行 $a$ 后到 $s'$ 的概率 | 由物理引擎决定（近确定性） |
| $R(s,a,s')$ | 奖励函数 | 执行动作后得到的即时奖励 | 每存活一步 +1 |
| $\gamma \in [0,1)$ | 折扣因子 | 未来奖励的衰减率 | 常用 0.99 |

**"马尔可夫"的含义**：$P(s_{t+1}|s_t,a_t)$ 只依赖当前状态和动作，**与更早的历史无关**。这是整套理论成立的前提——如果状态表示不满足马尔可夫性（比如只看位置不看速度），算法会表现异常。**实践中"状态设计"出问题，绝大多数是马尔可夫性不满足。**

**策略** $\pi(a|s)$ 是从状态到动作分布的映射。目标是找到最优策略 $\pi^*$ 最大化期望回报。

### 3.2 回报与折扣

从 $t$ 时刻起的**折扣回报**：

$$G_t = r_{t+1} + \gamma r_{t+2} + \gamma^2 r_{t+3} + \cdots = \sum_{k=0}^{\infty} \gamma^k r_{t+k+1}$$

**为什么要折扣**：

1. **数学上**：$\gamma < 1$ 保证无穷级数收敛（CartPole 若不截断会无限存活）
2. **物理上**：越远期的奖励越不确定——现在能拿到 1 分，比"100 步后可能拿到 10 分"更可靠
3. **偏差-方差**：$\gamma$ 小 → 更看重近期，方差低但可能短视；$\gamma$ 大 → 有远见但方差高

**实测印证**：REINFORCE 在 CartPole 上用 $\gamma=0.99$。若改 $\gamma=0.9$，等效视野约 10 步，而 CartPole 需要平衡几百步，会学不好。这类超参不是随便填的。

### 3.3 价值函数与贝尔曼方程

**状态价值函数**（在策略 $\pi$ 下，从 $s$ 出发的期望回报）：

$$V^\pi(s) = \mathbb{E}_\pi[G_t \mid s_t = s]$$

**动作价值函数**：

$$Q^\pi(s,a) = \mathbb{E}_\pi[G_t \mid s_t = s, a_t = a]$$

**贝尔曼期望方程**（把"期望回报"拆成"当前奖励 + 下一步的期望回报"）：

$$V^\pi(s) = \sum_a \pi(a|s) \sum_{s', r} p(s', r|s, a)\big[r + \gamma V^\pi(s')\big]$$

$$Q^\pi(s,a) = \sum_{s', r} p(s', r|s, a)\big[r + \gamma \sum_{a'} \pi(a'|s') Q^\pi(s', a')\big]$$

**贝尔曼最优方程**（最优策略下，把"对动作求期望"换成"取最大"）：

$$V^*(s) = \max_a \sum_{s', r} p(s', r|s, a)\big[r + \gamma V^*(s')\big]$$

$$Q^*(s,a) = \sum_{s', r} p(s', r|s, a)\big[r + \gamma \max_{a'} Q^*(s', a')\big]$$

**贝尔曼方程为什么是整个 RL 的地基**：

- **它把"无限求和"变成"递归"**。$V^\pi$ 的定义含无穷多项，贝尔曼方程把它压成一个自指方程，可以直接迭代求解（价值迭代、策略迭代）。
- **它是所有 TD 算法的目标**。DQN 的损失就是让 $Q(s,a)$ 逼近 $r + \gamma \max_{a'} Q(s',a')$——右边这个式子就是贝尔曼最优方程去掉期望后的单样本估计。
- **它是"自举"（bootstrapping）的来源**：用自己当前的估计去更新自己。这是 RL 区别于监督学习最本质的地方。

**一个容易混淆的点**：期望方程和最优方程的区别只在 $\sum_a \pi(a|s)$ 还是 $\max_a$。前者评价**某个给定策略**，后者求**最优策略**。DQN 用 max（off-policy，学最优 Q），REINFORCE 用策略自身采样（on-policy，评价并改进当前策略）。

### 3.4 策略梯度定理（手推）

**目标函数**（策略参数 $\theta$ 下，从初始分布出发的期望回报）：

$$J(\theta) = \mathbb{E}_{\tau \sim \pi_\theta}\left[G(\tau)\right] = \mathbb{E}_{\tau \sim \pi_\theta}\left[\sum_{t=0}^{T} \gamma^t r_{t+1}\right]$$

**要解决的问题**：$J(\theta)$ 依赖轨迹期望，而轨迹是**采样出来的离散动作序列**。动作采样不可导（$\arg\max$ 或 `Categorical.sample()` 没有梯度），**不能直接对 $J$ 求梯度**。

**推导（用到 log-derivative trick）**：

**第 1 步**：把期望写成对轨迹概率的积分：

$$\nabla_\theta J(\theta) = \nabla_\theta \int p_\theta(\tau) G(\tau) d\tau = \int \nabla_\theta p_\theta(\tau) G(\tau) d\tau$$

**第 2 步**：用恒等式 $\nabla_\theta p_\theta = p_\theta \nabla_\theta \log p_\theta$（因为 $\nabla \log p = \frac{\nabla p}{p}$）：

$$\nabla_\theta J(\theta) = \int p_\theta(\tau)\, \nabla_\theta \log p_\theta(\tau)\, G(\tau) d\tau = \mathbb{E}_{\tau \sim \pi_\theta}\big[\nabla_\theta \log p_\theta(\tau) \cdot G(\tau)\big]$$

**第 3 步**：展开轨迹概率。一条轨迹 $\tau = (s_0, a_0, s_1, a_1, \ldots)$ 的概率是：

$$p_\theta(\tau) = \rho(s_0) \prod_{t=0}^{T-1} \pi_\theta(a_t|s_t)\, p(s_{t+1}|s_t, a_t)$$

取对数：

$$\log p_\theta(\tau) = \log \rho(s_0) + \sum_{t=0}^{T-1} \log \pi_\theta(a_t|s_t) + \sum_{t=0}^{T-1} \log p(s_{t+1}|s_t, a_t)$$

**第 4 步（关键）**：对 $\theta$ 求导。**第一项和第三项都不含 $\theta$，直接消失**：

$$\nabla_\theta \log p_\theta(\tau) = \sum_{t=0}^{T-1} \nabla_\theta \log \pi_\theta(a_t|s_t)$$

**这一步是策略梯度最漂亮的地方：环境动力学 $p(s'|s,a)$ 不见了。** 意味着**不需要知道环境的转移模型**（model-free），只要能从环境采样就能估梯度。这也是它能用于 Isaac Lab 这类黑盒仿真器的原因。

**第 5 步**：代回，并利用**因果性**把 $G(\tau)$ 换成 $G_t$（$t$ 时刻的动作只能影响 $t$ 之后的奖励，之前的奖励与 $a_t$ 无关，期望为零）：

$$\boxed{\nabla_\theta J(\theta) = \mathbb{E}_{\pi_\theta}\left[\sum_{t=0}^{T-1} \nabla_\theta \log \pi_\theta(a_t|s_t)\, G_t\right]}$$

**这就是策略梯度定理。** 直观理解：**如果一条轨迹的回报高，就提高这条轨迹里所有动作的概率；回报低就降低。**

**漏洞与修补**：直接用 $G_t$ 作权重，方差极大（同一状态下，回报的随机性完全反映到梯度上）。引入**基线** $b(s)$：

$$\nabla_\theta J = \mathbb{E}\big[\nabla_\theta \log \pi_\theta(a_t|s_t)\,(G_t - b(s_t))\big]$$

**为什么减去基线不引入偏差**：

$$\mathbb{E}_{a \sim \pi_\theta}\big[\nabla_\theta \log \pi_\theta(a|s)\, b(s)\big] = b(s) \sum_a \nabla_\theta \pi_\theta(a|s) = b(s)\, \nabla_\theta \underbrace{\sum_a \pi_\theta(a|s)}_{=1} = 0$$

（因为 $\nabla_\theta \log \pi = \frac{\nabla_\theta \pi}{\pi}$，且 $\sum_a \pi = 1$ 的梯度为零。）

**常用基线是状态价值函数 $V(s)$**，此时 $G_t - V(s_t)$ 就是**优势函数**的蒙特卡洛估计。A3 的 PPO 用的 GAE 就是这个量的更好估计。

### 3.5 REINFORCE：策略梯度的最直接实现

把定理里的期望换成单条轨迹的采样，就是 REINFORCE：

1. 用当前策略 $\pi_\theta$ 跑完一整条轨迹
2. 算每步的回报 $G_t$
3. 计算梯度 $\sum_t \nabla_\theta \log \pi_\theta(a_t|s_t)(G_t - V_\phi(s_t))$
4. 梯度上升更新 $\theta$（同时用回归 $V_\phi(s_t) \to G_t$ 更新基线）

**关键特征**：

- **必须跑完整条轨迹**才能算 $G_t$（因为要回溯累加未来奖励）
- **是 on-policy 的**：采样用的策略就是被更新的策略
- **方差高**：一条轨迹的回报是单样本估计
- **无偏**：不引入自举，不依赖 $V$ 的准确性（$V$ 只降方差，不影响正确性）

**这三点是后面所有算法的出发点**：A2C 用自举降方差（引入偏差），PPO 用重要性采样让一条轨迹能更新多次（提高数据效率），DQN 换成学 Q 函数（off-policy）。

### 3.6 on-policy 与 off-policy（验收标准 5 的答案）

| | **on-policy** | **off-policy** |
|---|---|---|
| 定义 | **行为策略 = 目标策略** | **行为策略 ≠ 目标策略** |
| 数据来源 | 必须用当前策略新采 | 可用旧策略、探索策略、人类演示的数据 |
| 数据复用 | **一次即弃**（策略变了数据就失效） | 可反复从 replay buffer 采样 |
| 数据效率 | 低 | 高 |
| 偏差/方差 | 无偏，方差高 | 有偏（自举 + max 算子），方差低 |
| 稳定性 | 较稳定 | 需要额外技巧（目标网络、双 Q、重要性采样） |
| 本项目实例 | **REINFORCE（A2）、PPO（A3）** | **DQN（A2）、SAC（A4）** |

**判据（怎么一眼分辨）**：看**用来更新网络的样本，是不是由正在更新的那个策略产生的**。

- REINFORCE：采完一条轨迹立刻更新策略，下次必须重新采 → **on-policy**
- DQN：把 $(s,a,r,s')$ 存进 replay buffer，更新时随机抽历史数据，那些数据来自很旧的策略 → **off-policy**

**DQN 为什么能 off-policy 而 REINFORCE 不能**：DQN 学的是 $Q^*(s,a)$（最优动作价值），这个目标**与生成数据的策略无关**——任何策略探索到的 $(s,a,r,s')$ 都是关于环境动力学和真实奖励的有效信息。而 REINFORCE 估的是"当前策略的期望回报"，策略一变，旧数据的估计目标就错了。

**off-policy 为什么要目标网络**：DQN 的更新目标是 $r + \gamma \max_{a'} Q_\theta(s',a')$，**目标里含正在更新的参数 $\theta$**，等于"追一个自己会跑的目标"（自举 + 函数逼近 + off-policy 被称为 **deadly triad**，三者同时出现容易发散）。目标网络 $\theta^-$ 每隔 N 步才同步一次，让目标暂时固定。

**为什么连续控制少用 DQN**：DQN 需要 $\max_{a'} Q(s',a')$。动作离散时可以枚举所有动作；**动作连续（如 7 维关节力矩）时无法穷举**，只能解一个内层优化问题。所以连续控制走 actor-critic 路线（DDPG/SAC：用 actor 直接输出动作，绕开 max）。**这是本计划 A4 学 SAC、B 模块做连续控制的直接原因。**

#### 4.1.1 一张表说明超参的重要性

同一条代码，只改超参，结果差 120 分：

| 配置 | 集数 | avg100 | 结论 |
|---|---|---|---|
| ent_coef=0.01, lr=1e-3, GPU | 900 | **375.0** | ❌ 卡在 375，永不上 475 |
| ent_coef=0.0, lr=3e-3, GPU | 1500 | 500.0（第 704 集达标） | ✅ |
| ent_coef=0.0, lr=3e-3, CPU | 1200 | 490.9（3 种子均值） | ✅ |

**为什么 ent_coef 从 0.01 改成 0 是关键**：

熵奖励 $- \beta H(\pi)$ 鼓励策略保持随机。但 CartPole 的**最优策略是确定性的**——每一步都精确地朝某个方向推，任何随机性都会让杆子倒下。

$\beta = 0.01$ 看似很小，但它在 500 步的回合里**每一步**都在奖励随机性，累积起来把策略钉在"接近最优但不完全确定"的位置，表现上限就是 375 左右。$\beta = 0$ 后策略能收敛到确定性行为，直接到 500（满分）。

**这个教训很重要**：熵奖励在探索不足时会救场（比如 A3 复杂任务），但在**简单且最优策略确定**的任务上，它是性能天花板。**不要默认"加了熵奖励更安全"。**

**为什么 lr 从 1e-3 提到 3e-3 也有用**：REINFORCE 的梯度方差大，梯度本身噪声重，小学习率下每步方向被噪声主导，走得慢。适当提高学习率配合梯度裁剪（`clip_grad_norm_` 1.0）反而更稳。

#### 4.1.2 一个反直觉的实测发现：CPU 比 GPU 快

| 设备 | 同样 1200 集预算 | 说明 |
|---|---|---|
| GPU (RTX 5070 Ti) | 268 s（到第 704 集达标） | 采样阶段每步只做**一个样本**的前向 |
| **CPU** | **54–98 s**（3 种子） | 反而快 3–5 倍 |

**原因**：REINFORCE 是**逐步采样**的算法，每步只对一个 4 维观测做前向。这种 batch=1 的小算子，GPU 的时间几乎全花在 **kernel 启动开销**上（一次 launch 约 5–10 μs，而实际计算不到 1 μs）。CPU 没有这个开销，小算子上反而占优。

**判断规则**（对后面所有阶段都适用）：

| 场景 | 用 GPU | 用 CPU |
|---|---|---|
| batch 大、模型大（Isaac Lab 数千环境并行、图像、Transformer） | ✅ | ❌ |
| batch=1 小网络逐步采样（CartPole/LunarLander 上的手写算法） | ❌ | ✅ |

**本项目里 GPU 真正该用的是 C/D 阶段**：Isaac Lab 一次并行几千个环境，batch 维度天然很大，那时候 GPU 才有意义。**A2 这种小任务是 CPU 的地盘。**

#### 4.2.1 为什么必须保存"最好的 checkpoint"

这是本阶段最有价值的一条工程经验。**同一套配置、同一个种子**：

| 取哪个模型 | LunarLander 得分 |
|---|---|
| 训练**结束**时的模型 | **174.6**（也不达标！） |
| 训练中**评估最好**的模型 | **278.4** |

**差 104 分。** 训练日志显示 `ep_rew_mean` 在 300k 步附近达到 242，之后掉到 179 —— DQN 训练**会退化**，不是单调变好。

**为什么会退化**：DQN 的更新目标 $r + \gamma\max_{a'}Q_{\theta^-}(s',a')$ 依赖自己学出的 Q 值。Q 值被高估时，策略会去追这些虚高的目标，一旦某个状态被高估就会扩散（自举的累积误差）。加上 $\varepsilon$ 探索衰减后策略过早收敛到次优，就回不来了。

**结论**：**"最后一个 epoch/step 的模型"从来不是最好的模型。** A1 里按最优 val_acc 存、这里按最优 eval 存，是同一条原则：**用独立的验证信号做模型选择**。

#### 4.2.2 试错记录（这些都失败了，但很有信息量）

| 配置 | 步数 | 结果 | 失败原因 |
|---|---|---|---|
| lr=5e-4，默认网络 | 300k | 190.0（差一点） | 步数不够 |
| lr=5e-4，默认网络 | 650k | 174.6 | **后期退化**，加步数无效 |
| lr=1e-3，默认网络 | 700k | 119.8 | **学习率过大**，Q 值震荡 |
| **SB3 RL-Zoo 官方配置** | 400k | **-102.1** | **配置与本机环境不兼容** |
| **lr=5e-4 + 保存最优** | 400k | **278.4** ✅ | — |

**两个关键教训**：

**① 加步数不等于变好。** 650k 比 300k 还差。RL 训练不是监督学习，**没有"训练越久越收敛"的保证**。所以必须边训边评估、保存最优。

**② 网上的调参不能照抄。** SB3 的 RL-Zoo 里有一个 LunarLander DQN 的官方调参（`net_arch=[256,256], lr=6.3e-4, learning_starts=0, gradient_steps=-1` 等），本机实测 400k 步只有 **-102**（一直在坠毁）。原因是那套配置针对的是 `LunarLander-v2` 和更早的 SB3/gym 版本，与现在的 `LunarLander-v3` + SB3 2.9 行为不同。

**这类"抄了反而更差"的情况很常见**，正确做法是：**拿官方配置做起点，但必须在自己环境里实测验证**，不要因为"这是官方推荐"就相信它。

### 4.3 两个算法对照（验收标准 5 的证据）

| | 手写 REINFORCE | SB3 DQN |
|---|---|---|
| 学的是什么 | 策略 $\pi_\theta(a\|s)$ | 动作价值 $Q_\theta(s,a)$ |
| 数据 | 必须现采现用 | replay buffer 反复抽 |
| 策略类型 | on-policy | off-policy |
| 训练完模型能退化吗 | 基本不会（无自举） | **会**（4.2.1 实测退化 104 分） |
| 本阶段成绩 | CartPole 490.9 | LunarLander 268.7 |

## 6. 踩坑与注意

### 6.1 SB3 不接受字符串环境名

```python
DQN("MlpPolicy", "CartPole-v1")   # ❌ ValueError: The environment is of type <class 'str'>
DQN("MlpPolicy", gym.make("CartPole-v1"))   # ✅ 传环境实例
```

SB3 需要一个 Gymnasium 环境对象，不是 ID 字符串。网上不少示例假设有 OpenAI Gym 兼容层，直接传字符串会失败。

### 6.2 evaluate_policy 需要 Monitor 包装

不包 `Monitor` 会警告"reported episode lengths and rewards may be modified"。评估时用 `Monitor(gym.make(...))` 包装。

### 6.3 Python 输出被管道缓冲

用 `| Select-Object` 或 `Tee-Object` 时 Python 的 stdout 变成管道，**默认 8KB 块缓冲**，训练中的进度日志会整段卡住不显示，看起来像"卡死"。

**解决**：脚本用 `python -u`，或设 `$env:PYTHONUNBUFFERED='1'`。这条对后面所有长时间训练都适用。
