## 4. 检查点 2：Python 节点显示实时画面

> 规则沿革（2026-10-20）：先定"用户自己写"，同日用户改为"**助手给完整代码，用户粘贴运行**"，按后者执行；想切回自己写随时说，验收标准不变。

### 4.1 功能规格

在 `ros2_ws/src/tb3_learning/tb3_learning/` 下新建 `camera_viewer.py`，实现一个 ROS 2 节点：

1. 订阅 `/camera/image_raw`，消息类型 `sensor_msgs/msg/Image`。
2. 每收到一帧：把消息里的一维字节数组还原成图像矩阵，用 OpenCV 弹窗显示。
3. 每 5 秒在终端打印一次实际收到的帧率（FPS）。
4. 在 `setup.py` 的 `console_scripts` 里注册入口：`camera_viewer = tb3_learning.camera_viewer:main`。
   - 注意：现有 setup.py 里 `console_scripts` 这个键写了两遍；Python 字典重复键时**后面的覆盖前面的**。合并为一块的方案见 4.3。
5. 运行方式：`ros2 run tb3_learning camera_viewer`。

### 4.2 功能要求（验收清单）

程序以 `ros2 run tb3_learning camera_viewer` 方式运行，要求：

1. 订阅 `/camera/image_raw`。
2. 每来一帧图像，把它显示在一个持续刷新的窗口里。
3. 窗口里的颜色要和 Gazebo 场景一致（柱子是红的就显示成红的，不允许红蓝颠倒）。
4. 终端每 5 秒打印一次这段时间实际收到的帧率。
5. Ctrl+C 干净退出，不留僵死的图像窗口。

入口注册与 setup.py 合并方案见 4.3。

### 4.3 参考实现

**整体作用**：把 Gazebo 里 waffle_pi 相机拍到的实时画面变成屏幕上一个能看的窗口，并报告实际帧率。CP1 只证明了"图像数据在 ROS 里流动"（Hz 数字），这一步让图像第一次被人眼看到。

**为什么需要它**：

1. 感知学习的第一课是"确认眼睛能看、看得对"（颜色不颠倒、画面跟着车动），CP3–CP5 的 ArUco 检测和测距都建立在"收到图像 → 处理"这条流水线上。
2. 不直接用现成看图工具（如 rqt_image_view）：它只能看、不能改。本节点就是 CP4"检测 ArUco"的底子——到时候只需要在回调里、显示之前插入检测代码。
3. 它同时是感知节点的最小模板：订阅 → 解码 → 处理 → 输出。后面的感知练习（深度、语义地图）都是这个骨架的扩展。

**使用**：完整代码粘贴到 `ros2_ws/src/tb3_learning/tb3_learning/camera_viewer.py`（新建）；`setup.py` 的两个重复 `console_scripts` 块合并为一个，注册 `camera_viewer = tb3_learning.camera_viewer:main`。逐段讲解见 2026-10-20 会话（每段中文注释已写明作用）。

## 5. 检查点 3：生成 ArUco 标记并贴图进入 Gazebo 世界（方案已实测验证）

### 5.1 整体作用与为什么

**整体作用**：做一块 0.3m×0.3m 的"海报板"，正面印着 ArUco 标记，竖在机器人出生点正前方 0.8 米处，让 waffle_pi 的相机能拍到它。它是 CP4（检测）和 CP5（测距）的"靶子"——没有真实存在的标记，检测和测距都无从谈起。

**为什么这步最麻烦**：把"一张图片"变成 Gazebo 里的"贴图材质"，在 Harmonic 里写法多样、坑多。2026-10-20 已在真实环境实测三种方案：

- ~~`<pbr><dielectric><albedo_map>`~~：gz-sim 不支持，世界直接加载失败；
- ~~OGRE 材质脚本（.material + texture_unit）~~：模型渲染成纯黑（ogre2 后端贴图不生效）；
- ✅ **`<pbr><metal><albedo_map>`**：贴图正常显示（白边呈中灰、黑色图案清晰），ArUco 可检测。

同时实测出的两个关键事实：

- **检测配方**：cv2 4.6 的 `detectMarkers` 默认参数检不出仿真渲染图，必须设 `cornerRefinementMethod = CORNER_REFINE_APRILTAG`（消融实验确认仅此一项即稳定检出，两种亮度下均通过）。CP4 节点必须带上这条。
- **cv2 4.6 的生成函数叫 `drawMarker`**（4.7 才改名 `generateImageMarker`），照新教程抄会报错。

### 5.2 资产（已在仓库就位，助手建好并验证）

关键参数（CP4/CP5 要用）：字典 `DICT_6X6_250`、标记 **id=0**、**黑色方块物理边长 0.24 m**（0.3 m 板 × 512/640）。

## 6. 检查点 4～5：检测标记、画框画轴、测出三维位置（代码已写好，等实机验证）

> 2026-10-20 起 CP4 与 CP5 合并为一个新节点 `camera_detector.py`。原计划让用户在 `camera_viewer` 上自己改，现按"助手给完整代码、用户粘贴运行"的规则执行；`camera_viewer` 保持原样不动，两个节点可各开各的。

### 6.1 整体作用与为什么

**整体作用**：在 CP2 相机画面的基础上，每帧自动跑 ArUco 检测，把认出的标记用绿框套住、画上 XYZ 坐标轴，并在终端打印标记中心相对相机的三维坐标 x/y/z（米）。**"看见"（CP2/CP3）升级为"认出"（CP4）和"量出"（CP5）**。

**为什么需要它**：

1. 感知流水线第一次加入"处理"环节：订阅→解码→显示，变成 订阅→解码→**检测→测距**→显示。此后所有感知练习都只在"处理"这一格换内容。
2. 标记的三维位置是阶段 9（深度）、阶段 11（语义地图）、阶段 12（手眼标定）的共同输入——"物体在相机坐标系下在哪"这条链路必须先打通。
3. 顺带在真实环境复核 CP3 的关键结论：仿真渲染图必须 `CORNER_REFINE_APRILTAG` 才能检出。

### 6.2 新建 `camera_detector.py`

路径：`ros2_ws/src/tb3_learning/tb3_learning/camera_detector.py`，内容见本节末尾完整代码。要点：

- 本机 cv2 是 **4.6.0**，`cv2.aruco.ArucoDetector` **不存在**（那是 4.7+），必须用旧式 `detectMarkers` / `estimatePoseSingleMarkers`（已实测确认）。
- 内参从 `/camera/camera_info` 的 `k`、`d` 实时取，不写死；没收到内参时只画框不测距。
- `MARKER_LENGTH = 0.24`：是**黑色方块**边长，不是 0.3 的板边长。填错会让测出的距离整体同比例偏差。

### 6.3 `setup.py` 注册入口

在 `console_scripts` 列表里加一行（保持现有的单块结构）：


### 6.6 CP5 误差核对（这步的"验收数据"）

标记在机器人出生点 (-2.0, -0.5, 0.32) 正前方 0.8 m 处，即 (-1.2, -0.5)。**先让小车原地不动**，读一组 z 值，和手算值对比：

| 量 | 手算预期 | 允许误差 |
|---|---|---|
| z（前后） | ≈ 0.77 m（标记距出生点 0.8 m，相机比车体中心略靠前、略抬高，实际约 0.75–0.80） | ± 0.05 m |
| y（上下） | ≈ −0.15 ~ −0.20 m（相机在 0.3 m 高附近，标记中心在 0.32 m，基本等高，所以 y 应接近 0；数值为负表示在光轴下方） | ± 0.05 m |
| x（左右） | ≈ 0.00 m（两者 y 坐标都是 −0.5，正前方无偏移） | ± 0.03 m |

判定方法：

- **z 在 0.72–0.85 之间** → CP5 通过。
- **z 明显不是这个量级**（如 0.1 或 3.0）→ 看 6.7 排查树。
- **想让证据更硬**：遥控小车沿直线前进 0.3 m 左右停下，再读 z——它应当减少约 0.3 m。相对误差比绝对值更能说明测距是否可信（绝对值的基准受相机安装位置影响）。

### 6.7 排查树

- **报 `ModuleNotFoundError: rclpy`** → 先 `deactivate`（新终端会自动激活项目 venv）。
- **报 `Package 'tb3_learning' not found`** → 漏了 `source install/setup.bash`（ros2_ws 的那个）。
- **画面正常但没有绿框** → ① `CORNER_REFINE_APRILTAG` 那行是否抄上；② 字典是否 `DICT_6X6_250`；③ 标记是否在画面里（先跑 camera_viewer 看一眼）。
- **有绿框但没有轴、没有位置日志** → 没收到 `/camera/camera_info`，检查终端是否有 `内参已就绪`；也可 `ros2 topic echo /camera/camera_info --once` 确认话题在发。
- **z 值约为真值一半或两倍** → `MARKER_LENGTH` 填错（0.12 或 0.48）。
- **z 值随距离线性缩放、x/y 也同比** → 内参错误（相机主点不在画面中心时会出现，WSL 下一般不会）。
- **build 报错** → 多半是 setup.py 加行时逗号/缩进问题，把报错原文发我。

### 6.8 通过标准

- **CP4 完成** = 绿框实时套在标记上 + 终端报 `id=[0]` + 遥控时框跟着标记走。
- **CP5 完成** = 终端持续打印 x/y/z，且静止时 z 落在 0.72–0.85 m；前进 0.3 m 后 z 相应减少约 0.3 m。

### 6.9 完整代码：`camera_detector.py`

```pythonimport rclpy
from rclpy.node import Node
from sensor_msgs.msg import Image, CameraInfo

import numpy as np
import cv2

DICTIONARY = cv2.aruco.getPredefinedDictionary(cv2.aruco.DICT_6X6_250)
MARKER_LENGTH = 0.24   # 黑色方块物理边长（米），不是板的 0.3


class CameraDetector(Node):

    def __init__(self):
        super().__init__('camera_detector')

        self.create_subscription(Image, '/camera/image_raw', self.image_callback, 10)

        self.camera_matrix = None      # 内参从 camera_info 取，不写死
        self.dist_coeffs = None
        self.create_subscription(CameraInfo, '/camera/camera_info', self.info_callback, 10)

        self.parameters = cv2.aruco.DetectorParameters_create()
        self.parameters.cornerRefinementMethod = cv2.aruco.CORNER_REFINE_APRILTAG

        self.frame_count = 0
        self.report_time = None
        self.first_detection = True

    def info_callback(self, msg: CameraInfo):
        if self.camera_matrix is not None:
            return
        self.camera_matrix = np.array(msg.k, dtype=np.float64).reshape(3, 3)
        self.dist_coeffs = np.array(msg.d, dtype=np.float64)
        self.get_logger().info(f'内参已就绪: fx={self.camera_matrix[0, 0]:.4f} '
                               f'cx={self.camera_matrix[0, 2]:.0f} cy={self.camera_matrix[1, 2]:.0f}')

    def image_callback(self, msg: Image):
        if msg.encoding == 'rgb8':
            img = np.frombuffer(msg.data, dtype=np.uint8).reshape(msg.height, msg.width, 3)
            img = cv2.cvtColor(img, cv2.COLOR_RGB2BGR)
        elif msg.encoding == 'bgr8':
            img = np.frombuffer(msg.data, dtype=np.uint8).reshape(msg.height, msg.width, 3)
        else:
            return

        gray = cv2.cvtColor(img, cv2.COLOR_BGR2GRAY)
        corners, ids, _ = cv2.aruco.detectMarkers(gray, DICTIONARY, parameters=self.parameters)

        if ids is not None:
            cv2.aruco.drawDetectedMarkers(img, corners, ids)   # 彩色框 + id
            if self.first_detection:
                self.first_detection = False
                self.get_logger().info(f'首次检测到标记, id={ids.flatten().tolist()}')

            if self.camera_matrix is not None:
                rvecs, tvecs, _ = cv2.aruco.estimatePoseSingleMarkers(
                    corners, MARKER_LENGTH, self.camera_matrix, self.dist_coeffs)
                for rvec, tvec in zip(rvecs, tvecs):
                    cv2.drawFrameAxes(img, self.camera_matrix, self.dist_coeffs,
                                      rvec, tvec, 0.1)          # XYZ 轴，轴长 0.1 m
                    t = tvec.ravel()
                    self.get_logger().info(f'标记位置: x={t[0]:+.3f} y={t[1]:+.3f} z={t[2]:+.3f} m')

        cv2.imshow('camera_detector', img)
        cv2.waitKey(1)

        self.frame_count += 1
        now = self.get_clock().now()
        if self.report_time is None:
            self.report_time = now
        elif (now - self.report_time).nanoseconds >= 5e9:
            seen = ids.flatten().tolist() if ids is not None else '无'
            self.get_logger().info(f'近 5 秒 {self.frame_count} 帧, 最新检测: {seen}')
            self.frame_count = 0
            self.report_time = now


def main(args=None):
    rclpy.init(args=args)
    node = CameraDetector()
    try:
        rclpy.spin(node)
    except KeyboardInterrupt:
        pass
    finally:
        cv2.destroyAllWindows()
        try:
            node.destroy_node()
        except Exception:
            pass
        if rclpy.ok():
            rclpy.shutdown()


if __name__ == '__main__':
    main()
```
