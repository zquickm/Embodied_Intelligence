# 阶段 0 详细操作步骤：安装软件并完成机器人仿真入门

> 如果电脑已经安装 Ubuntu 22.04，请不要按本文安装 Jazzy；改用 [阶段0_Ubuntu22.04安装步骤.md](D:\Embodied_Intelligence\file\阶段0_Ubuntu22.04安装步骤.md)，采用 ROS 2 Humble 路线。

## 1. 阶段 0 的完成目标

阶段 0 完成时，你的电脑应当能够：

1. 进入 Ubuntu 24.04 桌面。
2. 正常运行 ROS 2 Jazzy 的发布者和订阅者示例。
3. 启动 Gazebo Harmonic。
4. 在 Gazebo 中显示 TurtleBot3 Burger。
5. 用键盘控制小车前进、转弯和停车。
6. 查看 `/cmd_vel`、`/odom`、`/joint_states`、`/tf` 和 `/scan` 等话题。
7. 在 RViz2 中观察机器人、雷达和坐标关系。
8. 运行一个 Python 节点，让小车低速前进两秒、自动停车并打印里程计位置。

这一阶段不需要购买机器人、单片机、电机驱动板或传感器。

## 2. 你需要下载或安装什么

### 2.1 在 Windows 中手动下载的两个文件

| 软件 | 用途 | 官方地址 |
|---|---|---|
| Ubuntu 24.04 LTS Desktop 64-bit ISO | 安装机器人开发使用的 Linux 系统 | [Ubuntu 24.04 官方镜像](https://releases.ubuntu.com/noble/) |
| Rufus | 把 Ubuntu ISO 写入 U 盘，制作启动盘 | [Rufus 官方网站](https://rufus.ie/) |

Ubuntu 下载页面可能同时展示更新的 Ubuntu 版本。这里必须选择 **24.04 LTS、Desktop、64-bit AMD64**，不要改成 26.04，因为 ROS 2 Jazzy 的主线平台是 Ubuntu 24.04 Noble。[ROS 2 Jazzy 支持平台](https://github.com/ros2/ros2_documentation/blob/rolling/source/Get-Started/Releases/Release-Jazzy-Jalisco.rst)

### 2.2 进入 Ubuntu 后通过软件源安装

- ROS 2 Jazzy Desktop：ROS 2、RViz2、示例和常用图形工具。
- ROS 开发工具：`rosdep`、构建工具和开发辅助程序。
- Git：下载 TurtleBot3 官方代码。
- colcon：构建 ROS 2 工作区。
- Gazebo Harmonic 与 `ros_gz`：机器人物理仿真及 ROS 2 通信。
- TurtleBot3 官方软件包：机器人模型、话题接口、键盘控制和仿真世界。

Gazebo 官方当前将 ROS 2 Jazzy 与 Gazebo Harmonic 配套，并可通过 ROS 软件源中的 vendor packages 安装。[Gazebo vendor packages 说明](https://gazebosim.org/docs/latest/ros2_gz_vendor_pkgs/)

### 2.3 现在不需要安装

- Arduino IDE。
- CUDA、cuDNN 或 NVIDIA 深度学习环境。
- Anaconda。
- Docker。
- ROS 1 Noetic。
- Windows 版 ROS 或 Windows 版 Gazebo。
- 单片机烧录器和电机调试软件。

这些软件与阶段 0 的目标无关，提前安装只会增加环境冲突。

## 3. 电脑和安装方式选择

### 3.1 实用配置建议

- 64 位 Intel 或 AMD 处理器。
- 内存最低 8 GB，建议 16 GB。
- 为 Ubuntu 预留至少 60 GB 空间，建议 100 GB 以上。
- 支持 OpenGL 的核显或独显。
- 一个至少 8 GB 的 U 盘。
- 安装期间使用稳定网络和电源。

8 GB 内存可以完成基础仿真，但同时运行 Gazebo、RViz2 和浏览器时可能吃紧。

### 3.2 推荐安装方式

优先顺序：

1. **单独硬盘安装 Ubuntu**：对已有 Windows 数据影响最小，最推荐。
2. **Windows 与 Ubuntu 双系统**：可以使用，但必须先备份数据并处理 BitLocker。
3. **虚拟机**：只适合先体验 ROS 命令，不建议作为 Gazebo 主线环境，显卡加速和 USB 设备容易增加额外问题。
4. **WSL2**：可以学习部分 ROS 命令，但不是本计划的主线；后续真实传感器、USB 串口和 Gazebo 图形环境更麻烦。

如果电脑只有一块存有重要数据的硬盘，又不熟悉分区，先准备第二块 SSD，或请熟悉双系统安装的人协助。不要直接试错分区。

## 4. Windows 安装前准备

### 4.1 备份

先把文档、代码、照片、浏览器资料和 BitLocker 恢复密钥备份到另一块硬盘或可信云端。双系统安装会修改磁盘分区，任何误选都可能造成数据丢失。

如果 Windows 开启了 BitLocker，应先确认恢复密钥已经保存。Ubuntu 官方提醒，启用 BitLocker 时安装器可能无法安全识别 Windows 分区。[Ubuntu 安装说明](https://ubuntu.com/tutorials/install-ubuntu-desktop)

### 4.2 下载 Ubuntu ISO

打开 [Ubuntu 24.04 官方镜像目录](https://releases.ubuntu.com/noble/)，下载文件名类似下面形式的镜像：

```text
ubuntu-24.04.x-desktop-amd64.iso
```

其中 `x` 是当前点版本编号，实际下载时以官网提供的最新 24.04.x 文件名为准。

不要把 ISO 直接下载到准备制作启动盘的 U 盘中。

### 4.3 校验 ISO

在 Windows PowerShell 中运行：

```powershell
Get-FileHash "C:\Users\你的用户名\Downloads\ubuntu-24.04.x-desktop-amd64.iso" -Algorithm SHA256
```

作用：计算下载文件的 SHA-256。把命令中的用户名和 ISO 文件名替换成你电脑上的真实路径，再将输出与 Ubuntu 镜像目录中的 `SHA256SUMS` 对比。二者一致说明文件没有下载损坏或被替换。

### 4.4 使用 Rufus 制作启动盘

1. 将 U 盘中的重要文件全部备份。
2. 打开 Rufus。
3. “设备”选择准备制作启动盘的 U 盘。
4. “引导类型选择”中选择刚下载的 Ubuntu ISO。
5. 现代电脑通常保持 GPT 和 UEFI；其余选项先保持默认。
6. 点击“开始”。如果询问写入模式，选择 ISO 镜像模式。
7. 再次核对目标确实是 U 盘，然后确认清除。
8. 等待状态变成“准备就绪”。

这一步会清空所选 U 盘。Ubuntu 官方也建议 Windows 用户使用 Rufus，并明确要求制作前备份 U 盘。[Ubuntu 启动盘说明](https://ubuntu.com/desktop/docs/en/latest/how-to/create-a-bootable-usb-stick/)

## 5. 安装 Ubuntu 24.04

### 5.1 先试用再安装

1. 保持 U 盘插入，重启电脑。
2. 开机时按启动菜单键，常见按键是 `F12`、`F2`、`Esc` 或 `F10`，具体以电脑品牌为准。
3. 选择 UEFI 模式的 USB 设备。
4. 进入 Ubuntu 安装界面后先选择“Try Ubuntu”。
5. 在试用桌面中检查 Wi-Fi、键盘、触控板、分辨率和声音是否正常。

如果试用环境已经黑屏或无法联网，先处理硬件兼容问题，不急着写入硬盘。

### 5.2 正式安装

1. 点击桌面的“Install Ubuntu”。
2. 选择语言、键盘和网络。
3. 允许安装第三方显卡和 Wi-Fi 驱动。
4. 有独立空硬盘时，确认选中的是那块硬盘。
5. 保留 Windows 时，选择安装器明确提供的“与 Windows 共存”选项。
6. **除非目标硬盘确定可以全部清空，否则不要选择“Erase disk”。**
7. 设置用户名、电脑名和密码。
8. 安装完成后重启，按提示拔掉 U 盘。

如果安装器没有显示“与 Windows 共存”，不要自行猜测分区，应先退出安装并检查 BitLocker、磁盘空间和启动模式。

## 6. 第一次进入 Ubuntu 后的检查

按 `Ctrl+Alt+T` 打开终端，执行：

```bash
cat /etc/os-release
uname -m
```

作用：第一条显示 Ubuntu 版本，应看到 `24.04` 或 `noble`；第二条显示处理器架构，普通 Intel/AMD 电脑应看到 `x86_64`。

更新系统：

```bash
sudo apt update
sudo apt upgrade -y
sudo reboot
```

作用：

- `sudo apt update` 更新软件包目录，不会直接升级软件。
- `sudo apt upgrade -y` 安装已发布的系统更新，`-y` 表示自动确认。
- `sudo reboot` 重启，让内核、驱动和系统更新完全生效。

`sudo` 会要求输入安装 Ubuntu 时设置的密码。输入过程中终端不显示星号，这是正常行为。

如果使用 NVIDIA 显卡，优先打开 Ubuntu 的“软件和更新 → 附加驱动”安装推荐驱动，不要从网络下载未知 `.run` 文件覆盖系统驱动。

## 7. 安装 ROS 2 Jazzy

以下步骤均在 Ubuntu 终端中执行。

### 7.1 准备语言环境和基础工具

```bash
locale
sudo apt update
sudo apt install locales software-properties-common curl git -y
sudo locale-gen en_US en_US.UTF-8
sudo update-locale LC_ALL=en_US.UTF-8 LANG=en_US.UTF-8
export LANG=en_US.UTF-8
sudo add-apt-repository universe
```

各命令作用：

- `locale`：查看当前字符编码环境。
- `apt install ...`：安装语言包、软件源管理工具、下载工具和 Git。
- `locale-gen`：生成 UTF-8 语言环境。
- `update-locale`：保存 UTF-8 为系统语言环境设置。
- `export LANG=...`：让当前终端立即使用 UTF-8。
- `add-apt-repository universe`：启用 ROS 2 部分依赖所在的 Ubuntu Universe 软件源。

### 7.2 添加 ROS 2 官方软件源

```bash
sudo apt update
sudo apt install curl -y
export ROS_APT_SOURCE_VERSION=$(curl -s https://api.github.com/repos/ros-infrastructure/ros-apt-source/releases/latest | grep -F "tag_name" | awk -F'"' '{print $4}')
curl -L -o /tmp/ros2-apt-source.deb "https://github.com/ros-infrastructure/ros-apt-source/releases/download/${ROS_APT_SOURCE_VERSION}/ros2-apt-source_${ROS_APT_SOURCE_VERSION}.$(. /etc/os-release && echo ${UBUNTU_CODENAME:-${VERSION_CODENAME}})_all.deb"
sudo dpkg -i /tmp/ros2-apt-source.deb
```

各命令作用：

- 第一、二条确保软件目录和 `curl` 可用。
- `export ROS_APT_SOURCE_VERSION=...`：从官方仓库读取最新的软件源配置版本号。
- `curl -L -o ...`：下载与当前 Ubuntu 代号匹配的 ROS 软件源安装包。
- `dpkg -i ...`：安装 ROS 软件源配置和签名信息。

这套方式来自 ROS 2 官方安装文档，比手工复制旧版密钥命令更不容易过期。[ROS 2 官方安装源配置](https://github.com/ros2/ros2_documentation/blob/rolling/source/Get-Started/Installation/Ubuntu-Install-Debs.rst)

### 7.3 安装桌面版 ROS 2

```bash
sudo apt update
sudo apt upgrade -y
sudo apt install ros-jazzy-desktop ros-dev-tools python3-colcon-common-extensions -y
```

作用：

- 前两条刷新 ROS 软件源并让 Ubuntu 保持最新。
- 最后一条安装 ROS 2 Jazzy Desktop、RViz2、示例、开发工具和 colcon 构建工具。

不要选择只有命令行基础组件的 `ros-jazzy-ros-base`，因为阶段 0 需要 RViz2 等图形工具。

### 7.4 设置每个终端自动加载 ROS 2

```bash
echo 'source /opt/ros/jazzy/setup.bash' >> ~/.bashrc
source ~/.bashrc
printenv ROS_DISTRO
```

作用：

- `echo ... >> ~/.bashrc`：把 ROS 环境加载命令追加到 Bash 配置文件，只需执行一次。
- `source ~/.bashrc`：让当前终端立即重新读取配置。
- `printenv ROS_DISTRO`：检查当前 ROS 发行版，正确输出应为 `jazzy`。

### 7.5 测试 ROS 2

打开第一个终端：

```bash
ros2 run demo_nodes_cpp talker
```

作用：启动 C++ 消息发布节点，持续发布示例文本。

再打开第二个终端：

```bash
ros2 run demo_nodes_py listener
```

作用：启动 Python 消息订阅节点。看到 `I heard` 表示两个节点已经通信成功。

测试完成后，在两个终端中分别按 `Ctrl+C` 停止程序。

## 8. 安装 Gazebo Harmonic

执行：

```bash
sudo apt update
sudo apt install ros-jazzy-ros-gz -y
source /opt/ros/jazzy/setup.bash
gz sim --version
```

作用：

- `ros-jazzy-ros-gz` 安装与 Jazzy 配套的 Gazebo Harmonic 组件和 ROS-Gazebo 桥接包。
- `source` 让当前终端找到 ROS 软件源提供的 Gazebo 程序。
- `gz sim --version` 查看 Gazebo Sim 版本；Harmonic 对应 Gazebo Sim 8.x。

不要同时另外安装多个不同版本的 Gazebo。先保持 Jazzy 默认的 Harmonic 配对，后续遇到明确功能需求再调整。

可运行一个 Gazebo 自带示例：

```bash
gz sim shapes.sdf
```

作用：打开包含基础几何体的物理仿真世界。首次启动可能需要下载资源。能看到窗口和几何体，并能点击运行按钮，说明基础图形环境可用。关闭窗口或在终端按 `Ctrl+C` 停止。

## 9. 安装 TurtleBot3 Jazzy 仿真

TurtleBot3 官方当前提供 `jazzy` 分支及 Gazebo Sim 启动文件。[TurtleBot3 官方仿真说明](https://emanual.robotis.com/docs/en/platform/turtlebot3/simulation/)

### 9.1 创建工作区并下载代码

```bash
source /opt/ros/jazzy/setup.bash
mkdir -p ~/turtlebot3_ws/src
cd ~/turtlebot3_ws/src
git clone -b jazzy https://github.com/ROBOTIS-GIT/DynamixelSDK.git
git clone -b jazzy https://github.com/ROBOTIS-GIT/turtlebot3_msgs.git
git clone -b jazzy https://github.com/ROBOTIS-GIT/turtlebot3.git
git clone -b jazzy https://github.com/ROBOTIS-GIT/turtlebot3_simulations.git
```

作用：

- `source` 加载基础 ROS 2 环境。
- `mkdir -p` 创建标准 ROS 2 工作区和源码目录。
- `cd` 进入源码目录。
- 四条 `git clone -b jazzy` 分别下载 Dynamixel 接口、消息定义、TurtleBot3 主程序和仿真程序，并固定使用 Jazzy 分支。

如果目录中已经存在同名仓库，不要重复执行对应的 `git clone`。

### 9.2 安装依赖

第一次使用 rosdep 时运行：

```bash
sudo rosdep init
rosdep update
```

作用：`rosdep init` 建立系统级依赖配置，只需成功运行一次；`rosdep update` 下载最新依赖索引。如果提示已经初始化，跳过第一条并继续第二条。

然后运行：

```bash
cd ~/turtlebot3_ws
rosdep install --from-paths src --ignore-src -r -y --rosdistro jazzy
```

作用：读取四个仓库的依赖声明，安装尚未存在的 Ubuntu/ROS 软件包；`--ignore-src` 表示不重复安装工作区源码里已经存在的包。

### 9.3 编译

```bash
cd ~/turtlebot3_ws
colcon build --symlink-install
```

作用：构建整个 TurtleBot3 工作区。`--symlink-install` 让 Python 文件和资源修改后更容易立即生效。

成功时，结尾会显示所有包完成，没有 `Failed`。如果内存较小导致编译进程被杀，可改用：

```bash
colcon build --symlink-install --executor sequential
```

作用：一次只构建一个包，速度较慢，但降低内存占用。

### 9.4 自动加载工作区和车型

```bash
echo 'source ~/turtlebot3_ws/install/setup.bash' >> ~/.bashrc
echo 'export TURTLEBOT3_MODEL=burger' >> ~/.bashrc
source ~/.bashrc
```

作用：

- 第一条让新终端自动找到自己编译的 TurtleBot3 包。
- 第二条把默认仿真车型设为 Burger。
- 第三条立即应用配置。

前两条各执行一次即可，不要反复追加。

验证软件包：

```bash
ros2 pkg prefix turtlebot3_gazebo
```

作用：显示 `turtlebot3_gazebo` 的安装路径。能够输出路径说明工作区已经加载。

## 10. 启动仿真并控制小车

### 10.1 终端 1：启动 Gazebo 世界

```bash
source ~/.bashrc
ros2 launch turtlebot3_gazebo empty_world.launch.py
```

作用：加载 ROS、TurtleBot3 环境并启动最简单的空白仿真世界。第一次启动会比之后慢。

先确认：

- Gazebo 窗口正常出现。
- TurtleBot3 Burger 模型可见。
- 点击运行后仿真时间向前走。
- 终端没有持续重复的红色错误。

### 10.2 终端 2：键盘控制

```bash
source ~/.bashrc
ros2 run turtlebot3_teleop teleop_keyboard
```

作用：启动 TurtleBot3 官方键盘控制节点。按照终端打印的按键说明，先小幅增加线速度，测试前进、转向和停止。操作时保持该终端获得键盘焦点。

不要一开始连续提高速度。阶段 0 只需要确认命令与运动方向对应。

### 10.3 终端 3：观察接口

```bash
ros2 topic list -t
```

作用：列出所有话题及消息类型。重点寻找 `/cmd_vel`、`/odom`、`/joint_states`、`/tf`、`/tf_static` 和 `/scan`。

```bash
ros2 topic info -v /cmd_vel
```

作用：查看速度话题的消息类型、发布者和订阅者。Jazzy 版 TurtleBot3 默认应使用 `geometry_msgs/msg/TwistStamped`，这是它与很多旧教程的关键区别。[TurtleBot3 Jazzy Bringup 说明](https://emanual.robotis.com/docs/en/platform/turtlebot3/bringup/)

```bash
ros2 topic echo --once /odom
```

作用：只显示一条里程计消息，确认其中有位置、方向和速度信息。

```bash
ros2 topic hz /odom
```

作用：统计里程计发布频率。观察数秒后按 `Ctrl+C` 停止统计。

```bash
ros2 topic echo --once /joint_states
```

作用：读取一条轮子关节状态，检查名称、位置和速度字段。

```bash
ros2 topic echo --once /scan
```

作用：读取一帧模拟激光雷达数据，检查角度范围和距离数组。

## 11. 在 RViz2 中观察机器人

保持 Gazebo 运行，再打开一个终端：

```bash
source ~/.bashrc
ros2 launch turtlebot3_bringup rviz2.launch.py
```

作用：使用 TurtleBot3 官方 RViz2 配置打开可视化界面。

在 RViz2 中检查：

- Fixed Frame 使用 `odom` 或官方配置给出的有效坐标系。
- RobotModel 能显示机器人模型。
- TF 能显示坐标树。
- LaserScan 能显示 `/scan` 的雷达点。

Gazebo 负责物理仿真，RViz2 负责显示 ROS 数据；两者用途不同，不是重复软件。

## 12. 运行阶段 0 Python 练习节点

本项目已经提供示例：[阶段0_ros练习节点.py](D:\Embodied_Intelligence\file\阶段0_ros练习节点.py)

把文件复制到 Ubuntu 用户目录，例如：

```text
~/stage0_move_and_odom.py
```

保持 TurtleBot3 仿真运行，先停止键盘控制节点，避免两个节点同时发布速度。然后执行：

```bash
source ~/.bashrc
python3 ~/stage0_move_and_odom.py
```

作用：启动一个 Python ROS 2 节点，以 0.05 m/s 前进两秒，之后持续发布零速度，同时订阅 `/odom` 并打印位置。按 `Ctrl+C` 退出时还会再发布一次停止命令。

预期现象：

- Gazebo 中小车缓慢向前移动一小段后停止。
- 终端每隔若干帧输出一次 `x`、`y` 位置。
- 小车停止后位置基本不再变化。

如果 `/cmd_vel` 实际类型不是 `TwistStamped`，先以 `ros2 topic info -v /cmd_vel` 的结果为准，不要盲目修改代码。当前示例针对官方 Jazzy 分支。

## 13. 常见问题排查

| 现象 | 原因与处理 |
|---|---|
| `ros2: command not found` | 当前终端没有加载 ROS。运行 `source /opt/ros/jazzy/setup.bash`。 |
| `package 'turtlebot3_gazebo' not found` | 工作区未编译或未加载。重新构建，然后运行 `source ~/turtlebot3_ws/install/setup.bash`。 |
| `rosdep init` 提示已存在 | 已经初始化，不是故障；直接运行 `rosdep update`。 |
| Gazebo 打开后黑屏或崩溃 | 优先检查显卡驱动和 OpenGL；若在虚拟机或 WSL2，先换到原生 Ubuntu 验证。 |
| Gazebo 有机器人但键盘不动 | 确认仿真处于运行状态、键盘终端有焦点，并检查 `/cmd_vel` 是否为 `TwistStamped`。 |
| 编译时出现 `Killed` | 通常是内存不足，使用 `--executor sequential` 顺序构建。 |
| GitHub 下载失败 | 先检查网络、时间和 DNS，不要随意改为来源不明的镜像脚本。 |
| RViz2 显示 `No transform` | 检查 Gazebo 启动是否完整、Fixed Frame 是否存在，以及 `/tf` 是否持续发布。 |
| 命令提示找不到 Jazzy 软件包 | 先确认系统确实是 Ubuntu 24.04，并确认 ROS 软件源安装成功。 |
