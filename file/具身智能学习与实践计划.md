## 2. 模块 A：深度学习与强化学习基础

### 2.1 交付物

- 能独立写出 PyTorch 训练循环（含数据加载、优化器、验证、保存）
- 实现并调通 PPO 与 SAC，能解释为什么用它们而非 DQN
- 一份 RL 实验报告：至少两个任务的训练曲线与失败分析

### 2.2 资源

| 类型 | 资源 | 说明 |
|---|---|---|
| 课程 | [Spinning Up in Deep RL](https://spinningup.openai.com/) | 最精简的 RL 入门，含代码 |
| 课程 | [蘑菇书 EasyRL](https://github.com/datawhalechina/easy-rl) | 中文，理论系统，配套代码 |
| 教材 | Sutton & Barto《强化学习导论》 | 查阅用，不建议从头读到尾 |
| 实操 | [Gymnasium](https://gymnasium.farama.org/) | 环境接口标准 |
| 实操 | [Stable-Baselines3](https://github.com/DLR-RM/stable-baselines3) | 先跑通，再自己实现 |

### 2.3 任务分解

1. **PyTorch 基础**（1-2 周）：张量、自动求导、`nn.Module`、DataLoader；手写一个 MNIST/回归任务的完整训练循环。
2. **RL 概念**（2 周）：MDP、贝尔曼方程、策略梯度、Actor-Critic；跑通 CartPole、LunarLander。
3. **PPO**（2 周）：先用 SB3 跑通，再手写实现，对比两者。
4. **SAC / DDPG**（2 周）：连续控制任务（Pendulum、Walker2d）。
5. **实验方法论**（1 周）：随机种子、多次实验、曲线置信区间、超参敏感性。

### 2.4 验收标准

- [ ] 能手写 PPO，在 LunarLander 上达到 200 分
- [ ] 能手写 SAC，在 Pendulum-v1 上收敛
- [ ] 能解释：on-policy vs off-policy、为什么 PPO 更稳定、为什么 SAC 更适合连续控制
- [ ] 能画出 3 个随机种子的训练曲线并说明方差

### 2.5 常见陷阱

- **只跑通不理解**：SB3 三行代码就能跑，但那不等于会。必须自己实现一遍。
- **跳过数学**：策略梯度推导看不懂，后面所有算法都是黑箱。
- **单种子实验**：RL 方差极大，单次运行的结果没有意义。

## 3. 模块 B：MuJoCo 与经典连续控制

### 3.1 为什么先学 MuJoCo 而不是直接上 Isaac Sim

| 维度 | MuJoCo | Isaac Sim |
|---|---|---|
| 安装 | `pip install mujoco`，1 分钟 | 数十 GB，配置复杂 |
| 迭代速度 | 秒级启动 | 分钟级启动 |
| 物理精度 | 黄金标准（接触、摩擦） | 也很好，但更新 |
| 并行训练 | 需自建（或用 mjlab） | 原生数千环境 |
| 学习曲线 | 平缓 | 陡峭 |

**结论：MuJoCo 用来学算法，Isaac Sim 用来做规模化训练。** 两者互补，不冲突。

### 3.2 交付物

- 在 MuJoCo 里训练一个机械臂够到目标的策略
- 能修改 XML 模型（改质量、摩擦、阻尼）并观察策略退化
- 一份"为什么仿真里的参数这么重要"的分析

### 3.3 资源

| 类型 | 资源 | 说明 |
|---|---|---|
| 官方 | [MuJoCo 文档](https://mujoco.readthedocs.io/) | 权威 |
| 示例 | [MuJoCo Python 示例](https://github.com/google-deepmind/mujoco/tree/main/python/mujoco) | 官方示例 |
| 教程 | [Gymnasium Mujoco 环境](https://gymnasium.farama.org/environments/mujoco/) | 现成任务 |
| 进阶 | [mjlab](https://pypi.org/project/mjlab/) | MuJoCo Warp GPU 并行，Isaac Lab 风格 API |
| 中文 | [Datawhale dive-into-embodied-ai](https://github.com/datawhalechina/dive-into-embodied-ai) 的"MuJoCo 机械臂与 DDPG"章节 | 中文实操 |

### 3.4 任务分解

1. **MuJoCo 基础**（1 周）：MJCF 格式、`mujoco` Python API、读状态、发控制。
2. **现成环境**（1 周）：跑通 `Reacher`、`Pusher`、`Ant` 等，理解观测/动作空间。
3. **机械臂任务**（2 周）：自建一个简单机械臂（或复用现成模型），定义奖励（距离、姿态、平滑度），训练够到目标。
4. **参数敏感性**（1 周）：改质量、摩擦、关节阻尼，记录策略成功率变化。
5. **域随机化初体验**（1 周）：训练时随机化物理参数，比较泛化能力。

### 3.5 验收标准

- [ ] 能在 MuJoCo 中自定义一个 MJCF 环境并训练到策略收敛
- [ ] 能解释奖励设计中"稀疏奖励为什么难训练"
- [ ] 能展示：物理参数改变后策略性能下降多少 + 随机化后恢复多少

### 3.6 常见陷阱

- **奖励设计靠猜**：先把任务拆成"接近->接触->抓取->抬升"分阶段，每阶段给对应奖励。
- **不记录实验**：物理参数、种子、超参必须记录，否则无法复现。
- **忽略接触**：MuJoCo 的接触求解器参数（`solref`/`solimp`）对抓取影响极大。

## 4. 模块 C：Isaac Sim / Isaac Lab

### 4.1 前置条件（重要）

**本地环境不确定性**：你的 RTX 5070 Ti 是 Blackwell 架构，Isaac Sim 官方要求里列的是 RTX 5080（同为 50 系）。社区报告 5080 上可运行。**但必须实测确认。**

**建议的验证顺序**：

1. 在 **Windows 侧**安装 Isaac Sim（不要在 WSL 里装，官方推荐 Windows/Linux 原生）
2. 运行 Isaac Sim Compatibility Checker
3. 打开一个自带示例场景，确认能渲染、不崩溃
4. 只有这步通过，才继续后面的内容

**如果本地跑不起来**，备选方案：
- 租用云 GPU（RTX 4090 / A6000 按小时计费）
- 只用 MuJoCo + mjlab 做并行训练（功能上能覆盖大部分 RL 需求）

> 安装参考：
> - [Isaac Sim Requirements](https://docs.isaacsim.omniverse.nvidia.com/latest/installation/requirements.html)
> - [Isaac Lab Pip 安装](https://isaac-sim.github.io/IsaacLab/main/source/setup/installation/isaaclab_pip_installation.html)（Isaac Sim 5.X 需要 Python 3.11）
> - [Isaac Lab Quickstart](https://isaac-sim.github.io/IsaacLab/main/source/setup/quickstart.html)

### 4.2 交付物

- 能在 Isaac Lab 里跑通一个官方训练任务
- 能在自定义场景里训练一个简单任务（如机械臂抓取）
- 一份性能记录：多少环境并行、达到多少 FPS、训练多久收敛

### 4.3 资源

| 类型 | 资源 | 说明 |
|---|---|---|
| 官方 | [Isaac Lab 文档](https://isaac-sim.github.io/IsaacLab/main/) | 权威，含教程 |
| 课程 | [NVIDIA 机器人开发学习路径](https://www.nvidia.cn/training/learning-path/robotics/) | 官方中文，含"Isaac Lab 入门" |
| 中文 | [Datawhale dive-into-embodied-ai](https://github.com/datawhalechina/dive-into-embodied-ai) "仿真工具"章节 | 快速上手对比 |

### 4.4 任务分解

1. **安装与验证**（2-3 天）：装 Isaac Sim，跑 Compatibility Checker，开示例场景。
2. **Isaac Lab 跑通**（1 周）：跑官方 `train` 命令，理解 `ManagerBasedRLEnvCfg` 的任务组织方式。
3. **自定义环境**（2 周）：改场景、改奖励、改观测，训练一个机械臂任务。
4. **规模化**（1 周）：调整并行环境数，测 FPS，找显存瓶颈。
5. **域随机化**（1-2 周）：随机化材质、光照、物理参数，对比泛化。

### 4.5 验收标准

- [ ] Isaac Sim 能正常渲染示例场景（无崩溃、无严重噪点）
- [ ] Isaac Lab 官方任务能训练到目标性能
- [ ] 能自定义一个任务并训练收敛
- [ ] 能说清楚：多少并行环境适合你的 16 GB 显存

### 4.6 常见陷阱

- **显存不足**：16 GB 是"最低"要求，传感器多的场景很容易爆。先用少量环境测试。
- **版本地狱**：Isaac Sim / Isaac Lab / PyTorch / Python 版本必须严格匹配。**记录所有版本号**。
- **WSL 陷阱**：如果非要在 WSL 里跑，渲染问题和驱动对接会消耗大量时间。优先 Windows 原生。

## 5. 模块 D：世界模型（核心方向）

### 5.1 为什么这是差异化所在

招聘信息里，"世界模型 / 视频预测 / model-based RL"与"VLA"并列为两大方向。相比 VLA（模型大、需要大量算力和数据），**世界模型的入门门槛更低、论文复现更容易、个人项目的说服力更强**。

**这个模块是区别于"只会跑 VLA 微调"的候选人的关键。**

### 5.2 交付物

- 从零实现一个世界模型（VAE 编码器 + RSSM 动力学 + 潜空间 Actor-Critic）
- 在至少 2 个任务上复现 Dreamer 的效果
- 一份世界模型诊断报告：预测误差、rollout 漂移、表征质量
- 一个创新点/改进尝试（哪怕失败也要有分析）

### 5.3 资源

| 类型 | 资源 | 说明 |
|---|---|---|
| **课程** | [Learn World Models（Datawhale）](https://datawhalechina.github.io/learn-world-model/) | **5 讲理论 + 6 个项目，中文，直接对口** |
| 论文 | DreamerV3（Nature 2025） | 必读，世界模型里程碑 |
| 论文 | RSSM 原始论文（DreamerV1/V2） | 理解潜在动力学 |
| 论文 | TD-MPC2 | 另一个主流规划范式 |
| 论文 | JEPA 系列（LeCun 路线） | 表征学习视角 |
| 代码 | [danijar/dreamerv3](https://github.com/danijar/dreamerv3) | 官方实现 |

> **强烈建议先做 Datawhale 的 Learn World Models 课程**。它的 6 个项目（P01-P06）正好是渐进式实现：VAE 编码器 -> RSSM -> Dreamer 智能体 -> 换 backbone -> 评估仪表盘 -> 反事实推断。**做完这套，就有了完整的世界模型实操能力。**

### 5.4 任务分解（跟随 Learn World Models 的路线）

| 阶段 | 理论学习 | 实操项目 | 时长 |
|---|---|---|---|
| 1 | L01 世界模型定义与来路 | — | 3 天 |
| 2 | L02 状态估计与观测编码 | **P01：训练 VAE 编码器** | 1 周 |
| 3 | L02 潜在动力学与 rollout | **P02：构建 RSSM** | 1-2 周 |
| 4 | L03 规划与控制 | **P03：训练 Dreamer 智能体** | 2 周 |
| 5 | L03 backbone 选择 | **P04：换成 Transformer** | 1 周 |
| 6 | L04 诊断世界模型 | **P05：评估仪表盘** | 1 周 |
| 7 | L04 + 反事实 | **P06：反事实世界模型** | 1-2 周 |
| 8 | L05 前沿思辨 | 阅读 + 写综述 | 1 周 |

### 5.5 验收标准

- [ ] 能解释 RSSM 的 prior/posterior 为什么要分开、KL 平衡怎么做
- [ ] 能训练 Dreamer 在至少 2 个任务上达到合理性能
- [ ] 能诊断世界模型：预测误差随时间如何增长、什么情况下 rollout 失效
- [ ] 能复现一篇论文的核心实验（哪怕是简化版）
- [ ] 有自己的改进尝试和失败分析

### 5.6 常见陷阱

- **跳过 P01/P02 直接跑 Dreamer**：会变成调包，理解不了。
- **只看预测误差不做控制**：世界模型的终极指标是"用于控制时的效果"，不是重建质量。
- **视野漂移不处理**：长 rollout 必然发散，要理解训练分布与自由 rollout 的差异（L02 重点）。

## 6. 模块 E：模仿学习与 VLA

### 6.1 交付物

- 完整走通一条模仿学习流程：数据采集 -> 训练 -> 仿真评测
- 复现 ACT 或 Diffusion Policy 之一

- 一份对比报告：不同方法的成功率、推理速度、数据需求

### 6.2 资源

| 类型 | 资源 | 说明 |
|---|---|---|
| 框架 | [LeRobot](https://github.com/huggingface/lerobot) | HuggingFace 的机器人学习框架 |
| 模型 | [SmolVLA](https://huggingface.co/docs/lerobot/smolvla) | 小体积 VLA，适合个人算力 |
| 仿真 | [LIBERO](https://huggingface.co/docs/lerobot/libero) | **无需硬件**，官方支持 |
| 模型 | [ACT / ALOHA](https://github.com/tonyzhaozh/act) | 双臂操作经典 |
| 模型 | Diffusion Policy | 扩散策略，与 ACT 并列主流 |
| 中文 | [Datawhale dive-into-embodied-ai](https://github.com/datawhalechina/dive-into-embodied-ai) 的"ACT 双臂操作训练" | 中文实操 |

### 6.3 任务分解

1. **模仿学习基础**（1 周）：行为克隆原理、数据格式、为什么需要动作分块（action chunking）。
2. **LIBERO 环境**（1 周）：跑通官方示例，理解任务定义和评测方式。
3. **复现 ACT**（2 周）：在 MuJoCo/ALOHA 仿真里训练一个抓取任务。
4. **VLA 微调**（2 周）：用 SmolVLA 在 LIBERO 上微调，测成功率。
5. **对比分析**（1 周）：ACT vs Diffusion Policy vs SmolVLA，同任务下的表现。

### 6.4 验收标准

- [ ] 能在 LIBERO 上完成一条完整的训练-评测流程
- [ ] 能解释 ACT 为什么用 CVAE、Diffusion Policy 为什么用扩散
- [ ] 能说清楚 VLA 的"动作 token 化"是什么
- [ ] 有至少 3 种方法的对比数据

### 6.5 与模块 D 的关系

**D 和 E 是并列的两条主线，选一条深挖即可。** 建议：

- 想做 **RL / 控制 / 世界模型**方向 -> 深挖 D，E 只做到"能讲清楚"程度
- 想做 **VLA / 大模型 / 模仿学习**方向 -> 深挖 E，D 只做到"能讲清楚"程度
- 两者都做深 -> 时间翻倍，除非全职学习

**建议以 D 为主**（世界模型门槛低、个人项目说服力强、算力要求低），E 作为补充。

### 10.1 触发条件

- 预算到位（建议 >= 2000 元）

### 10.2 优先级

| 优先级 | 硬件 | 用途 | 价格区间 | 说明 |

## 11. 执行建议

### 11.1 第一周该做什么

**第 1 天：验证 Isaac Sim 能否跑**

这是整个计划的**关键分叉点**。如果 5070 Ti 跑不了，C 模块要改成云 GPU 或纯 MuJoCo 方案，影响后续所有安排。

```
1. 在 Windows 侧下载 Isaac Sim（约 6-8 GB）
2. 安装后运行 Compatibility Checker
3. 打开示例场景，确认渲染正常
```

**如果通过**：按 A -> B -> C 顺序走。
**如果不通过**：跳过 C 的本地部分，改用 MuJoCo + mjlab 做并行训练，或租云 GPU。

**第 2-7 天：开始模块 A**

不要等 Isaac Sim 装完再做别的。**A 模块完全不依赖 Isaac Sim**，可以先跑起来。

### 11.2 每周节奏建议

| 环节 | 时间占比 | 说明 |
|---|---|---|
| 理论学习 | 30% | 论文、课程 |
| 编码实现 | 50% | 自己写，不要复制 |
| 记录复盘 | 20% | 实验日志、失败分析 |

**记录比学习更重要。** 面试时能拿出来的不是"我学过"，而是"我做过并且知道为什么这么做"。

### 11.3 里程碑检查点

| 时间 | 应该达到 |

| 3 个月 | B 模块完成，MuJoCo 里能训练自定义任务 |

## 14. 说明与免责

### 14.1 关于时间估算

所有时间估算基于"每周 15 小时"假设。如果投入不同，按比例调整。**不要因为进度落后就压缩学习深度**——面试看的是能不能讲清楚，不是学了多少模块。

### 14.2 关于硬件

新版把硬件推迟到模块 I，但这**不等于硬件不重要**。真实机器人经验在面试中仍然是加分项，尤其是能讲清楚 sim2real gap 的候选人。建议在仿真能力足够后，尽快补一次真实的机械臂经验。

### 14.3 关于方向选择

模块 D（世界模型）和 E（VLA）是并列的两大方向。本文档建议以 D 为主，但**这个建议基于"世界模型入门门槛较低、个人项目说服力较强"的判断**。如果你对 VLA 更感兴趣，完全可以对调优先级。

### 14.4 待自行核实的信息

以下信息随时间变化，建议定期自查：

- 具体公司的岗位要求（本文引用的 JD 是 2026-10 的快照）
- Isaac Sim 对 RTX 50 系的支持状况（社区仍在更新）
- 各框架的最新版本与 API（Isaac Lab、LeRobot 更新频繁）
