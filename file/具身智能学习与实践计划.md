## 1. 世界模型路线：确定走 A 路线

> **v4/v5 定位（2026-10-26）**：目标岗改为开发岗后，世界模型线从"核心竞争力"降为**面试差异化 + 一个 demo（D1/D3）**。本节保留完整路线对比，因为面试要能讲清三条路线的对立与收敛；但 D4–D9 已暂停，见第 14 节降级清单。

### 1.1 三条路线对比

| | **A. 交互式/控制导向** | B. 表征式（JEPA） | C. 生成式（视频） |
|---|---|---|---|
| 核心思想 | 隐空间建模动力学，在想象中训练策略或规划 | 只预测抽象嵌入，不重建像素 | 直接生成未来帧/视频 |
| 代表工作 | DreamerV1/V2/V3、TD-MPC2、MuZero | I-JEPA、V-JEPA、V-JEPA 2、DINO-WM | Sora、Cosmos、Genie/Genie-2 |
| 能否直接控制 | 原生支持 | 需另接 planner | 需转成策略 |
| 算力需求 | 低（单卡可训） | 中 | 高 |
| 16 GB 显存可行性 | 完全够 | 只能小规模 | 只能微调/推理 |
| 对应岗位 | model-based RL / 机器人 RL | 研究岗 | 大厂研究院 |

> 三条路线在 2024–2026 出现明显**收敛趋势**（生成式加动作条件、JEPA 接规划、Dreamer 换大骨干），面试时能讲清对立与收敛是加分项。
> 参考：[综述](https://arxiv.org/html/2608.23070v1)、[Awesome-World-Modeling](https://github.com/OpenEnvision/Awesome-World-Modeling)

### 1.2 为什么选 A

1. **算力匹配**：C 路线视频扩散在 16 GB 上做不了有意义的工作；A 路线单卡轻松
2. **直接对口**：JD 里"model-based RL"正是 A 路线的核心
3. **有现成路径**：[Datawhale Learn World Models](https://datawhalechina.github.io/learn-world-model/) 的 6 个项目完整覆盖 A 路线，中文递进
4. **可验证**：每个阶段都有明确指标（预测误差、成功率），不靠"感觉学会了"

### 1.3 三条路线的投入权重

| 路线 | 投入 | 目标 |
|---|---|---|
| **A** | **主攻，做到能复现 + 有改进** | 核心竞争力 |
| B（JEPA） | 理解级，跑通小规模 | 面试能讲清表征式与生成式差异 |
| C（生成式） | 认知级，跑推理 demo | 知道 Cosmos/Genie 在做什么 |

#### A5 怎么读图（2026-10-26 补，回答"std 和均值线是什么"）

**三张产物回答三个不同问题，不要混着看：**

| 产物 | 回答什么 | 比较的对象 |
|---|---|---|
| `a5_cartpole_3seed.png` | 这个配置**稳不稳** | **同一个配置**的 3 个种子（三根细线超参完全相同） |
| `a5_sensitivity.png` | 改这个超参**有没有影响** | **不同配置**（同一超参的 3 个取值）的均值 + 误差棒 |
| `a5_hyperparam_table.md` | 影响**显不显著** | 把"均值差 vs std"算成结论 |

**关键**：3 种子图里三根细线是**同一个配置**跑三次，所以那张图**不是**用来比参数好坏的；比参数用敏感性图和表。

**std 是什么**：它量化"你未控制的因素造成了多大分散"。具体是三个：网络初始权重、每集初始状态序列、动作采样的随机结果。**std 有两层，含义不同：**

| | 曲线内的抖动 | 曲线间的分散 |
|---|---|---|
| 现象 | 同一条线上第 300 集 320 分、301 集 480 分 | seed 0 第 400 集收敛，seed 1 第 700 集才收敛 |
| 来源 | 策略相同，初始状态的运气不同 | **训练过程本身**的随机性 |
| 怎么处理 | 滑动平均就能平滑 | 平滑不掉，**必须靠多种子量化** |
| 图上位置 | 细线上的毛刺 | 细线之间的间距 + 灰色带宽度 |

**std 大小决定单次结果能不能报**：CartPole 三种子 490.2/490.7/491.8，std≈0.8 → 单次可信；LunarLander 259.1/268.7/278.4，std≈9.7 → 种子间差 19 分，**单次结果不能对外说**。

**均值是什么**：在这个配置、这个任务、这个预算下的**典型表现**，不是抽象的"参数质量"。参数质量不存在独立属性——换任务、换预算就变。

**但不能只比均值**。反例：

| 配置 | 三种子 | 均值 | 种子间 std | 结论 |
|---|---|---|---|---|
| lr=3e-3（默认） | 488/491/490 | 489.7 | 1.3 | — |
| lr=1e-3 | 470/495/486 | 483.7 | 10.4 | 均值差 6.0 < 噪声 10.4 → **测不出来** |

只看均值会误判"1e-3 更差"。正例：gamma=0.90 三种子 120/95/140，均值 118.3、std 18.9 —— std 也不小，但均值差 371 ≫ 噪声 → **有影响**。

**所以 A5 的唯一判据**：`|均值差| > 噪声` 才叫有影响；否则只能说"当前种子数和预算下测不出来"。

> **std 口径统一为样本标准差（ddof=1）**，与 A2 文档报的"268.7 ± 9.7"一致（ddof=0 会得 7.88，两处口径不同会让文档自相矛盾）。

#### A5 实测结果（2026-10-26 跑完 21 个配置）

**数据**：21 条 run（CartPole + REINFORCE，固定 1200 集预算，seed 0/1/2）。产物见 `file/assets/a5_*.png`、`a5_hyperparam_table.md`、`a5_stability_table.md`、`a5_runs.json`。

**第一个发现：默认配置的 `final` 是 291.0，看起来比所有变体都差——这个结论是错的。**

逐种子明细暴露了原因：

| lr | gamma | hidden | seed | final | peak | 达标集数 |
|---|---|---|---|---|---|---|
| 0.003 | 0.99 | 128 | 0 | 363.8 | **500.0** | 409 |
| 0.003 | 0.99 | 128 | 1 | **9.3** | **500.0** | 531 |
| 0.003 | 0.99 | 128 | 2 | 500.0 | 500.0 | 401 |

seed 1 在第 531 集打到 500 分，训练结束时只剩 9.3 分（比随机策略还差）。**REINFORCE 达标之后崩溃了**，默认配置 3 个种子里 2 个如此。所以 `final` 测的是"崩溃后剩多少"，不是"学到什么"。

**第二个发现：`peak` 在 CartPole 上饱和了**（9 个配置里 7 个 peak=500.0，std=0）。任何够好的配置都能撞天花板，用 peak 比超参只会得到"都一样"的假结论。

**结论：单一指标没法判断，必须三指标并列。**

| 指标 | 测什么 | 局限 |
|---|---|---|
| `peak` | 最终能到多高 | **饱和**，只能发现"学不会"的配置 |
| `solved` / `eps` | 学得快不快（样本效率） | eps 只对达标种子平均，含**幸存者偏差** |
| `崩溃种子数` / `drop` | 学到的会不会丢 | 崩溃不是噪声，是算法/步长缺陷 |

**实测结论（`a5_hyperparam_table.md` 判断列由脚本按"解决率 → 崩溃数 → eps 差异"优先级自动生成）**：

1. **lr=1e-2 最差**：3/3 崩溃、2/3 达标、peak 445.9 ± 78.3 —— 步长过大直接发散
2. **gamma=0.90 学不会**：只有 2/3 达标，峰值 486.4 —— 视野约 10 步，撑不住 CartPole 要的几百步（与预期一致）
3. **hidden=32/64 优于 128**：三种子全达标、**0/3 崩溃**、drop 仅 10–20 分；而 128 崩 2/3
4. **lr=1e-3 最稳但最慢**：0/3 崩溃、drop 17 分，但 eps 692 集（默认 447）—— 慢 55%
5. gamma=0.95 不显著（各指标在波动范围内）

**最有价值的一条**：**默认配置不够好**。A2 当时用 `--stop_on_solve` 提前停，掩盖了崩溃；A5 用固定 1200 集预算才暴露出来。**A2 的 490.9 是"峰值成绩"，不是"训练结束成绩"** —— 这个区别以后对外报数据时必须说清。

**还没做（可选）**：LunarLander 3 种子曲线（DQN 慢，30–90 分钟）。

**修正记录**：
- v1 脚本用 `final` 做判据 → 得出"默认配置最差"的错误结论，已改为三指标
- v1 判据只比 peak → peak 饱和后无区分度，已改为按解决率/崩溃数/eps 优先级判断
- std 口径 ddof=0 → ddof=1，与 A2 文档一致

1. **轨迹随机性**：同策略不同种子采到的轨迹不同，回报方差天生就大

  - [ ] 能修改 RewardCfg 并观察到训练行为变化（**需 3 个种子，见下方说明**）
  - [ ] 能解释 Direct 工作流与 Manager-based 工作流的适用场景

> **为什么是 7 个而不是 5 个**：原计划只列 5 个，漏了 `Command` 和 `Curriculum`。实测 `ReachEnvCfg`（C1 已训过的任务）用到的是 **7 个**：
>
> | 管理器 | Reach-Franka 实例 | 职责 |
> |---|---|---|
> | `observations` | 1 个 group（`policy`） | 把场景状态转成策略输入 |
> | `actions` | 2 个（`arm_action`、`gripper_action`） | 把策略输出转成关节指令 |
> | `rewards` | 6 项 | 标量化任务目标 |
> | `terminations` | 2 项（`success`、`time_out`） | 判定回合结束 |
> | `events` | 1 项（`reset_robot_joints`） | reset/setup/interval 时的域随机化与状态重置 |
> | **`commands`** | 1 项（`ee_pose`） | **生成并管理指令/目标**——没有它就没有"要到哪去" |
> | **`curriculum`** | 2 项（`action_rate`、`joint_vel`） | **按训练进度动态调难度/权重** |
>
> **漏掉 `commands` 的后果最严重**：机械臂任务的目标位置来自 command manager，不理解它就改不动任务目标。漏掉 `curriculum` 则无法解释"为什么同一权重前期不惩罚、后期才惩罚"。

> **"观察到训练行为变化"必须配 A5 的纪律**：单次训练曲线的变化可能只是随机波动。**做法：改奖励前后各跑 3 个种子，比较均值±方差；只有当两组分布不重叠时才能称为"行为变化"。** 这正是 C2 排在 A5 之后的原因。

### 13.1 面试讲点与踩坑清单（从已删文档提炼，v5 保留的核心）

**A1（PyTorch 与训练循环）**
- 手写循环：Dataset/DataLoader、优化器、验证、checkpoint、AMP；三种子 0.98993 ± 0.00060
- 反直觉实测：**MNIST 小模型上 AMP 慢约 11%**——小模型 kernel 启动开销大于混合精度收益
- val loss 单点抖动 ≠ 过拟合；过拟合点以"val loss 持续回升"判断（本阶段 epoch 7）
- 踩坑（真实踩到）：分段粘贴代码时三个 `def` 继承了类的缩进，**全部变成类方法**，模块级报 `NameError`。语法合法、`py_compile` 不报错、错在定义处却指向调用处
  - 10 秒确认法：`python -c "import ast; t=ast.parse(open(r'文件',encoding='utf-8').read()); print([n.name for n in t.body if isinstance(n,(ast.FunctionDef,ast.ClassDef))])"`，看函数是否在顶层
  - 通用教训：**Python 靠缩进定作用域**，多段拼接时缩进就是语义；写嵌套结构（如 D2 的 RSSM）必查

**A2（RL 基本概念）**
- **CPU 比 GPU 快 3–5 倍**：小网络逐步采样时，GPU 时间全花在 kernel 启动上 → A2/B 类小任务一律 `device='cpu'`
- 熵系数是天花板：`ent_coef=0.01` 时 CartPole 卡 375，改 0 到 500（最优策略是确定性的）
- DQN 必须保存**训练中评估最好**的 checkpoint：同配置同种子，训练中最好 279.4，结束时 174.6
- 网上 RL-Zoo 的 LunarLander 配置在本机实测失效（400k 步 -102），不要照抄
- 手推过：策略梯度（log-derivative trick + 基线无偏性）、贝尔曼期望/最优方程、MDP 五元组
- on/off-policy 不是背概念：REINFORCE（on）与 DQN（off）是自己跑出来的两个实例
- 踩坑：SB3 不接受字符串环境名；`evaluate_policy` 需要 `Monitor` 包装；Python 输出经管道会被缓冲

**C0 / C1（Isaac Sim / Isaac Lab）**
- 官方默认迭代数远超需要：Cartpole 只用 30%、Reach 只用 18%
- Cartpole 的 `Metrics/success_rate` 恒为 1.0、无区分度，**必须看回合长度**
- Isaac Lab 3.0 默认物理后端是 `newton_mjwarp`（Newton + MuJoCo Warp），不是 PhysX
- 训练日志默认写"当前目录"；在 WSL 仓库里跑会经 9P 写到 `\\wsl.localhost\...`，既污染仓库又拖慢训练 → 在 `D:\isaac\work` 跑，`.gitignore` 已加 `logs/`

**阶段 0 / 1S（ROS 2 与感知）**
- ROS 2 Jazzy + Gazebo Harmonic + turtlebot3 链路可用；话题 `/cmd_vel`、`/odom`、`/joint_states`、`/tf`、`/scan`
- ArUco：有效检测 0.6–1.5 m；相机实际安装高 0.11 m；Gazebo 相机约 8 Hz
- 这些数字来自 Gazebo，**不能直接搬到 Isaac Sim**，F1 需重测（这本身可作"验证仿真器差异"的对照记录）

**阶段一（硬件选型，已暂停）**
- 结论：**百元级预算买不到资料完整的闭环底盘**，缺件补齐后总成本更高；不在型号与载荷未定时推荐单一型号
- 采购前必须冻结载荷/尺寸/接口/资料要求；到货按"静态检查→悬空低速→落地低速→反馈→断联"顺序验收

### 17.4 pip 装包的安全流程（硬规则）

Isaac 环境的依赖 pin 很脆。**任何 `pip install` 前必须先 dry-run**：

```powershell
python -m pip install --dry-run "包名==版本"          # 第 1 步：看会发生什么
python -m pip freeze | Out-File D:\isaac\work\pipfreeze_before.txt -Encoding UTF8
python -m pip install "包名==版本"
python -m pip freeze | Out-File D:\isaac\work\pipfreeze_after.txt -Encoding UTF8
Compare-Object (Get-Content D:\isaac\work\pipfreeze_before.txt) (Get-Content D:\isaac\work\pipfreeze_after.txt)
```

**判据**：只有 `=>`（新增）→ 安全；出现 `<=`（删除/版本变更）→ **停下**，查这个包为什么动了 pin。
**装完必须回归**：`isaaclab train --task Isaac-Cartpole --num_envs 256 --max_iterations 20`，确认没被破坏。
**实证**：2026-10-21 装 Box2D/SB3/pygame-ce/pandas，dry-run 只新增 5 个包，`Compare-Object` 确认 0 变更，回归 exit=0。

### 17.6 坑清单（按踩到频率）

1. **中文控制台编码崩溃**：报 `UnicodeEncodeError: 'gbk' codec ...`，因为 Isaac Lab 横幅含 `▛`。解法：`PYTHONUTF8=1`（activate.ps1 已含）。
2. **`.ps1` 必须 UTF-8 with BOM**：无 BOM 的中文脚本在 PowerShell 5.1 下按 GBK 解码，解析报错。`.md`/`.py` 保持 UTF-8 无 BOM。
3. **pip 25.3 不能升**：升到 26 触发 PEP 658 严格校验，装 Isaac 时 `BadMetadata` 崩溃。
4. **PowerShell 5.1 的 `Get-Content` 默认 GBK**：读中文 .md 会乱码，加 `-Encoding UTF8`；写文件用 `[System.IO.File]::WriteAllText`。
5. **git push 报 schannel 握手失败**：`git -c http.sslBackend=openssl push origin main`（已写入仓库配置）；代理不是根因。
6. **训练日志写到当前目录**：在仓库里跑会生成 `logs/`（经 9P 写入极慢），一律在 `D:\isaac\work` 跑。
7. **`OMNI_KIT_ACCEPT_EULA` 每个新窗口都要设**：否则 `import isaacsim` 卡在询问。
8. **内存偏紧**：48 GB 里 WSL + Isaac 会吃掉一大半（验证时 Free 12.5 GB）。跑 Isaac 前关掉 WSL 里的 Gazebo/RViz，或给 WSL 设内存上限。
9. **C 盘紧张（约 6 GB）**：`TEMP`/`TMP`/`PIP_CACHE_DIR` 必须指向 D 盘——`PIP_CACHE_DIR` 只管缓存，**不管临时文件**，两者是不同目录（这是当初装失败的原因）。

### 17.7 WSL（ROS 2）与 Windows（Isaac Sim）分工

**为什么分居**：Isaac Sim 只在 Windows 侧装好；ROS 2 Jazzy 只有 Ubuntu 24.04 官方支持。**不要为了让两者同框去重装任何一边。**

| 内容 | 在哪做 | 注意 |
|---|---|---|
| Isaac Sim / Isaac Lab / C2–C4 | Windows（`D:\isaac\env`） | 照旧，先激活 |
| C++ / ROS 2 / G 模块 / 八股练习 | WSL（Ubuntu 24.04 + Jazzy） | 在 `~/projects` 重新 clone，**绝不在 `/mnt/d` 上 colcon 编译** |
| H' 联调 | 只做一次 | 先离线、后实时 |

**WSL 恢复命令**（ROS 2 Jazzy、Gazebo Harmonic、turtlebot3 仍在 WSL 里，只需重建仓库）：

```bash
cd ~/projects && git clone https://github.com/zquickm/Embodied_Intelligence.git
```

**H' 联调两种方案**：
- **b（先做，保交付）**：Isaac 侧导出数据（图像/状态/动作）→ ROS 2 侧 `ros2 bag` 回放或离线节点消费。
- **a（锦上添花）**：Isaac Sim 启用 ROS 2 bridge 扩展，WSL 与 Windows 设同一 `ROS_DOMAIN_ID`，用 CycloneDDS/FastDDS 走网络；坑在 WSL2 网络模式与防火墙。

**代价**：切换成本。规则：**C++/ROS 2 练习不与 Isaac 同框**，只在 H' 阶段联调一次。

### 17.8 环境重建要点（万一要重装，按这个顺序）

1. **C 盘必须先腾空间**：`$env:TEMP="D:\isaac\temp"`、`$env:TMP` 同上、`$env:PIP_CACHE_DIR="D:\isaac\pipcache"`（只在当前窗口有效）
2. **pip 降到 <26**：`python -m pip install "pip<26"`（最终锁 25.3）
3. **装 Isaac Sim**：`python -m pip install isaacsim[all,extscache]==6.2.0.0 --extra-index-url https://pypi.nvidia.com`
4. **torch 换 GPU 版**（PyPI 的 Windows torch 是 CPU-only）：`pip install --index-url https://download.pytorch.org/whl/cu128 --force-reinstall --no-deps "torch==2.11.0+cu128" "torchvision==0.26.0+cu128" "torchaudio==2.11.0+cu128"`
   - 坑：直接 `pip install torch==2.11.0` 会因 PEP 440 本地版本号规则判定 `2.11.0+cpu` 已满足，**什么都不装**

6. **对齐被带跑的包**：`pip install "numba==0.63.1" "click==8.3.3" "psutil==5.9.8"`；urllib3 冲突留着不管
7. **验证**：`isaaclab train --rl_library rsl_rl --task Isaac-Cartpole --num_envs 64 --max_iterations 30`，期望退出码 0、约 7000 steps/sec（64 环境）

## 20. 说明

### 20.1 为什么不设时间表

时间估算依赖"每周投入多少小时"这个未确认的变量，且 RL 实验耗时波动极大（一次训练可能 10 分钟也可能 10 小时）。用阶段 + 验收标准替代后：进度判断客观化（标准是否达成）、不受投入时长变化影响、换节奏时计划不用重写。

**唯一注意别在某个阶段卡太久**：某条验收标准反复失败超过 5 次尝试，记录问题、暂时降级该标准、继续推进，回头再补。

### 20.2 关于硬件

硬件推迟到模块 I 不等于硬件不重要。真实机器人经验仍是加分项，尤其能讲清 sim2real gap 的候选人。仿真能力足够后应尽快补一次真机经验；若走嵌入式方向（不推荐），见 16.3。

### 20.3 待补充的信息

随时间变化，定期自查：目标公司 JD（本文快照为 2026-10）、Isaac Sim / Isaac Lab 版本、世界模型三条路线的进展。
