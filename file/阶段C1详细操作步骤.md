## 2. 前置条件

### 2.1 环境变量（每个新窗口都要设）

```powershell
$env:OMNI_KIT_ACCEPT_EULA = "YES"
$env:TEMP = "D:\isaac\temp"
$env:TMP = "D:\isaac\temp"
$env:PYTHONUTF8 = "1"
$env:PYTHONIOENCODING = "utf-8"
[Console]::OutputEncoding = [System.Text.Encoding]::UTF8
```

**为什么每条都需要**：

| 变量 | 作用 | 不设会怎样 |
|---|---|---|
| `OMNI_KIT_ACCEPT_EULA` | 自动接受许可证 | 卡在交互式询问 |
| `TEMP` / `TMP` | 临时文件放 D 盘 | C 盘被撑爆（只剩 9 GB） |
| `PYTHONUTF8` | Python 用 UTF-8 模式 | **启动横幅的制表符导致 GBK 编码崩溃** |
| `PYTHONIOENCODING` | 标准输出编码 | 同上 |
| `Console::OutputEncoding` | 控制台输出编码 | 日志乱码 |

**⚠️ 最后三条是这次发现的坑**：在中文 Windows（GBK 代码页 936）下，Isaac Lab 启动时会打印带制表符的 banner（`▛` 等字符），
GBK 无法编码，直接抛 `UnicodeEncodeError: 'gbk' codec can't encode character '\u259b'`，训练还没开始就崩了。

**这不是 Isaac Lab 的 bug，是终端编码问题。** 用 `PYTHONUTF8=1` 即可绕过。

### 2.2 独立工作目录

```powershell
New-Item -ItemType Directory -Force -Path D:\isaac\work | Out-Null
Set-Location D:\isaac\work
```

**为什么必须换目录**：训练日志默认写到**当前工作目录**的 `logs/` 下。如果当前目录是 WSL 项目路径，
日志会通过 9P 文件系统写入，既慢又会污染 git 仓库。

## 3. 任务一：Isaac-Cartpole（✅ 已完成）

### 3.1 命令

```powershell
Set-Location D:\isaac\work
D:\isaac\env\Scripts\isaaclab.exe train --rl_library rsl_rl `
    --task Isaac-Cartpole --num_envs 4096 --max_iterations 150
```

**参数含义**：
- `--rl_library rsl_rl`：用 RSL-RL 的 PPO 实现（Isaac Lab 默认，NVIDIA 自研，工业界常用）
- `--task Isaac-Cartpole`：任务名，必须是 `list_envs` 里存在的
- `--num_envs 4096`：并行环境数。GPU 上几千个环境同时跑，这是 Isaac Lab 相对 CPU 仿真的核心优势
- `--max_iterations 150`：训练轮数。**取任务配置的默认值**（Cartpole 的 `CartpolePPORunnerCfg.max_iterations = 150`）

### 3.2 实测结果

```
Task            Isaac-Cartpole
Workflow        manager-based
RL library      rsl_rl
Physics         newton_mjwarp
Device          cuda:0
Environments    4096

Training time: 28.35 秒（150 轮）

最终指标：
  Metrics/success_rate:            1.0000   ← 100% 成功率，已完全收敛
  Episode_Termination/time_out:    1.0000   ← 所有回合都撑到时间上限
  Episode_Reward/alive:            1.0000   ← 存活奖励拿满
  Episode_Reward/pole_pos:        -0.0080   ← 杆子几乎不倾斜
```

**吞吐量**：

```
150 轮 × 16 步/轮 × 4096 环境 = 9,830,400 环境步
9,830,400 / 28.35 s ≈ 34.7 万 steps/sec
```

**对比**：之前用 64 个环境时只有约 7000 steps/sec。**并行环境数从 64 提到 4096，吞吐提升约 50 倍** —— 这就是 Isaac Lab 的价值。

### 3.3 训练曲线（关键节点）

| 迭代 | Mean episode length | 说明 |
|---|---|---|
| 0 | 12.78 | 随机策略，很快倒 |
| 1 | 29.84 | 开始有反应 |
| ~10 | 104.06 | 快速上升期 |
| 150 | 300（time_out） | 完全学会，撑满回合 |

**Cartpole 的回合上限是 300 步**（`episode_length_s=5`，`sim.dt=1/120`，`decimation=2` → 环境步长 1/60 秒 → 300 步）。
`time_out: 1.0` 说明所有回合都跑满 300 步，杆子没倒。

### 3.4 收敛判据

Cartpole 看两个指标，同时满足才算收敛：

- `Metrics/success_rate` ≥ 0.95
- `Episode_Termination/time_out` ≥ 0.95（说明不是靠提前终止"作弊"）

## 4. 任务二：Isaac-Reach-Franka（✅ 已完成）

### 4.1 为什么选这个任务

| 候选 | 训练量 | 选/不选的理由 |
|---|---|---|
| **Isaac-Reach-Franka** | 1000 轮 × 24 步 | ✅ **选它**：机械臂够物，直接对应后续 D9（世界模型接机械臂）任务 |
| Isaac-Ant | 1500 轮 | 四足运动，物理更复杂，可作为第三个任务 |
| Isaac-Lift-Franka | 更长 | 抓取抬升，难度高，留到 C3 自定义任务时参考 |

**选 Reach-Franka 的核心原因**：C3/D9 都要在机械臂上做，先用官方机械臂任务熟悉 Franka 的观测/动作空间，后面改起来有基础。

### 4.2 任务配置（从源码读出）

```
max_iterations   = 1000        ← 默认训练轮数
num_steps_per_env = 24         ← 每轮每环境采样步数
save_interval    = 50          ← 每 50 轮存 checkpoint
experiment_name  = "reach_franka"
default_agent    = "rsl_rl"    ← 默认后端就是 rsl_rl
actor 网络       = [64, 64]    ← 很小的 MLP
critic 网络      = [64, 64]
```

**注意 actor 只有 64×64 两层** —— 比 Cartpole 的 32×32 大不了多少。说明 Reach 是个相对简单的任务，重点在接触动力学而非网络容量。

### 4.3 命令

```powershell
Set-Location D:\isaac\work
D:\isaac\env\Scripts\isaaclab.exe train --rl_library rsl_rl `
    --task Isaac-Reach-Franka --num_envs 4096 --max_iterations 1000
```

### 4.4 实测结果

```
Task            Isaac-Reach-Franka
Workflow        manager-based
RL library      rsl_rl
Physics         newton_mjwarp
Device          cuda:0
Environments    4096

Training time:  443.33 秒（7 分 13 秒，1000 轮）
Iteration time: 0.35 s

最终指标：
  Metrics/success_rate:                 1.0000   ← 100% 成功率
  Metrics/ee_pose/position_error:       0.0466   ← 末端位置误差 4.66 cm
  Metrics/ee_pose/orientation_error:    0.1827   ← 姿态误差 0.18 rad ≈ 10.5°
  Episode_Termination/success:          1.0000   ← 全部以成功终止
  Episode_Termination/time_out:         0.0000   ← 无超时（不是靠超时"混"过去的）
```

**吞吐量**：

```
1000 轮 × 24 步/轮 × 4096 环境 = 98,304,000 环境步
98,304,000 / 443.33 s ≈ 22.2 万 steps/sec
```

**比 Cartpole 慢约 36%**（34.7 万 → 22.2 万），原因：机械臂是多刚体链，接触计算比倒立摆重得多。

### 4.5 训练过程观察

| 阶段 | Mean episode length | 现象 |
|---|---|---|
| 早期 | 19.6 → 43.1 → 68.0 | 回合变长，说明在摸索但还没成功 |
| 后期 | 34.8 → 30.2 → 33.1 | **回合变短了** |

**回合变短不是变差，是变好**：策略学会后会在 33 步左右就达成目标并**提前终止**（`Episode_Termination/success: 1.0`）。
早期回合长是因为它完不成任务，只能耗到时间上限。

**这是判断"是否真学会"的关键**：如果回合长度一直不下降而 success 很低，说明它在"磨时间"而不是"完成目标"。

### 4.6 play 回放验证

```powershell
D:\isaac\env\Scripts\isaaclab.exe play --rl_library rsl_rl `
    --task Isaac-Reach-Franka `
    --checkpoint "D:\isaac\work\logs\rsl_rl\reach_franka\2026-10-21_10-23-31\model_999.pt" `
    --num_envs 16 --real-time
```

**关键输出**：

```
[INFO] Loading experiment from directory: D:\isaac\work\logs\rsl_rl\reach_franka
[3/3] Loading policy
Environment device: cuda:0
Number of environments: 16
```

**验证结论**：checkpoint 能被正确加载，环境正常创建，策略进入运行循环，无报错。

**注意**：`play` 没有 `--headless` 参数，会开 GUI 窗口并**一直运行不退出**，看完手动关闭即可。

**checkpoint 位置规律**：

```
logs/rsl_rl/<experiment_name>/<时间戳>/model_<迭代号>.pt
```

`save_interval` 决定存多少：Cartpole 存了 4 个，Reach-Franka 每 50 轮存一个共 21 个。

### 4.7 收敛曲线与一个反直觉的发现

**数据来源**：训练目录下的 `events.out.tfevents.*`，用 TensorBoard 的 `EventAccumulator` 解析。

#### Cartpole（用回合长度判断，上限 300 步）

| 阈值 | 首次达到的迭代 |
|---|---|
| ≥ 200 步 | 27 |
| ≥ 250 步 | 39 |
| ≥ 280 步 | 42 |
| ≥ 295 步 | **45** |

采样点：`(0, 13) → (25, 183) → (50, 298) → (75, 300) → (100, 300)`

**收敛点约 45–50 轮。**

#### Reach-Franka（用 success_rate 判断）

| 阈值 | 首次达到的迭代 |
|---|---|
| ≥ 0.10 | 40 |
| ≥ 0.50 | 100 |
| ≥ 0.90 | 140 |
| ≥ 0.95 | 150 |
| ≥ 0.99 | **176** |

position_error 曲线（米）：

```
(0, 0.24) → (100, 0.14) → (200, 0.05) → (300, 0.044) → 之后稳定在 0.043~0.046
```

**收敛点约 150–176 轮。**

#### 发现：默认迭代数远超实际需要

| 任务 | 默认 max_iterations | 实际收敛迭代 | 余量 |
|---|---|---|---|
| Cartpole | 150 | ~45 | **只用了 30%** |
| Reach-Franka | 1000 | ~176 | **只用了 18%** |

**结论**：官方配置给的迭代数很宽松，是为了保证不同硬件/随机种子下都能收敛。

**对自己的影响**：
- 调参实验时**不必跑满默认轮数**，跑到收敛就停，能省 70–80% 时间
- 但正式跑基线时要跑满，否则不同种子的对比不公平
- 判断收敛最省事的办法：训练时看 TensorBoard，或在 `--max_iterations` 设小一点看曲线是否已平

#### 一个必须注意的陷阱：Cartpole 的 `Metrics/success_rate` 没用

Cartpole 的 `Metrics/success_rate` **从迭代 0 开始就是 1.0**，全程不变。

这不是 bug，而是它的定义方式对这个任务没有区分度。**如果只看这个指标，会误以为策略一开始就学会了。**

**正确做法**：Cartpole 看 `Train/mean_episode_length`（从 13 涨到 300 才是真学会），并配合 `Episode_Termination/time_out`。

**通用教训**：拿到一个新任务，先确认"哪个指标能真实反映学习进度"，不要默认 success_rate 一定可用。验证方法：看它在迭代 0 时是否就已经是高分——如果是，这个指标当前无效。

### 4.8 两个任务的收敛判据对比

跑完之后才看清：**这两个任务的判据不能用同一套逻辑**。

| 任务 | 可用指标 | 不可用指标 | 判断方式 |
|---|---|---|---|
| Isaac-Cartpole | `Train/mean_episode_length`、`Episode_Termination/time_out` | ❌ `Metrics/success_rate`（恒为 1.0） | 回合长度接近 300 且 time_out=1.0 |
| Isaac-Reach-Franka | `Metrics/success_rate`（有区分度） | — | success_rate ≥ 0.95 且位置误差稳定 |

**Reach 确实有 `Metrics/success_rate`**（这点我最初判断错了，以为它只有连续 reward）。
它的定义是"末端是否在容差内到位"，是个真正的二元指标，从 0.0 爬到 1.0，很适合判断收敛。

**Reach 的辅助指标**：

- `Metrics/ee_pose/position_error`：末端到目标距离，从 0.24 m 降到 0.044 m 后稳定 → 说明到达了物理精度极限
- `Metrics/ee_pose/orientation_error`：姿态误差 0.18 rad ≈ 10.5° → 姿态精度明显低于位置精度，这是多关节链的典型现象

**教训**：不要预设"这个任务应该有/没有某个指标"。先跑一次，把 TensorBoard 里所有 scalar 看一遍，再决定用哪个。

## 5. 数据记录表（C1 的核心产出）

每个任务跑完填一行。这张表是 C2/C3 调参的基线，也是面试时"你做过什么规模训练"的证据。

| 任务 | 环境数 | 迭代数 | 训练时长 | steps/sec | 显存占用 | 最终性能 | 收敛迭代 |
|---|---|---|---|---|---|---|---|
| Isaac-Cartpole | 4096 | 150 | 28.35 s | ~347,000 | < 1 GB | 回合长度 300/300（满） | **~45** |
| Isaac-Reach-Franka | 4096 | 1000 | 443.33 s | ~222,000 | 908 MiB | success_rate=1.0，位置误差 4.66 cm | **~176** |
| （可选）Isaac-Ant | 待定 | 1500 | — | — | — | — | — |

**显存占用怎么测**：训练运行时另开一个窗口执行：

```powershell
nvidia-smi --query-gpu=memory.used,memory.total,utilization.gpu --format=csv -l 2
```

`-l 2` 表示每 2 秒刷新一次。记下训练稳定期的 `memory.used` 峰值。

**判据**：显存峰值超过 15 GB 就要降环境数。16 GB 卡留 1 GB 余量给驱动和桌面。

## 7. 踩坑记录

### 7.1 Windows 中文控制台编码崩溃（本次遇到）

**现象**：训练刚启动就退出，报 `UnicodeEncodeError: 'gbk' codec can't encode character '\u259b'`

**原因**：中文 Windows 控制台默认代码页 936（GBK），Isaac Lab 启动横幅含制表符（`▛` `▜` 等），GBK 无法编码。

**解决**：设 `$env:PYTHONUTF8 = "1"`。

**注意**：这个坑在之前几次测试中没触发，因为当时输出经过了不同的管道处理。**正式训练建议每次都设**。

### 7.2 训练日志写到 WSL 路径

**现象**：训练完成后项目仓库里多了 `logs/` 目录。

**原因**：日志写到"当前工作目录"的 `logs/` 下；当时 shell 在 WSL 项目路径。

**解决**：`Set-Location D:\isaac\work` 后再训练；已在 `.gitignore` 加 `logs/` 兜底。

### 7.3 pip 不要升级

当前锁定 pip 25.3。升到 26 会触发 PEP 658 严格校验报错（详见《IsaacSim安装与验证记录.md》3.2 节）。
